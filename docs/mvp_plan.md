# RoxyPlan MVP 与版本规划

## 1. 分析视角

本文从产品经理角度分析 RoxyPlan 当前规划。

核心问题不是“能不能做”，而是“先做什么才能最快验证产品价值”。

RoxyPlan 的长期愿景很大，包括桌宠、聊天、长期记忆、人格系统、知识投喂、成长日志、语音、手机版和跨端陪伴。  
但早期产品必须收敛，否则会同时面对过多技术风险和体验风险。

产品核心假设：

- 用户愿意让一个 AI 以桌宠形式长期留在桌面。
- 用户愿意和 Roxy 持续聊天，而不是只把它当工具。
- 长期记忆能显著增强陪伴感。
- 成长记录和知识投喂能把 Roxy 从聊天工具变成个人长期伙伴。

MVP 的任务是验证前三个假设，不是一次性完成所有愿景。

## 2. 必须有的功能

### 2.1 桌宠入口

必须有。

原因：

- 桌宠是 RoxyPlan 区别于普通聊天机器人的第一识别点。
- 如果没有桌宠，产品会变成普通 AI 聊天窗口。
- 桌宠不需要复杂动画，但必须作为稳定入口存在。

最低要求：

- 桌面上有 Roxy 头像。
- 点击可以打开聊天窗口。
- 可以移动位置。
- 可以隐藏或退出。

### 2.2 聊天窗口

必须有。

原因：

- 聊天是陪伴体验的核心交互。
- 所有记忆、成长、监督、投喂最终都需要通过对话体现。

最低要求：

- 用户可以输入文字。
- Roxy 可以回复。
- 可以看到当前会话内容。
- 交互稳定、清楚、不卡顿。

### 2.3 基础人格设定

必须有。

原因：

- RoxyPlan 的价值不是单纯回答，而是“洛琪希”这个角色。
- 没有人格边界，陪伴感会不稳定。
- 早期就需要确定语气、禁止行为和陪伴规则。

最低要求：

- 温柔、清楚、克制的说话风格。
- 不制造依赖。
- 不羞辱用户。
- 不做医疗诊断。
- 不自动保存敏感记忆。

### 2.4 基础聊天记录

必须有。

原因：

- 没有聊天记录，长期陪伴很难成立。
- 聊天记录是后续记忆提取、复盘和成长分析的基础。

最低要求：

- 保存消息内容。
- 保存时间。
- 区分用户和 Roxy。
- 支持读取最近对话。

### 2.5 基础长期记忆

必须有，但必须非常克制。

原因：

- 长期记忆是 RoxyPlan 的核心卖点。
- 但早期做复杂记忆系统风险很高。

最低要求：

- 保存用户称呼。
- 保存用户明确要求记住的偏好。
- 保存少量长期目标。
- 用户可以查看和删除记忆。
- 保存前需要确认。

### 2.6 基础设置

必须有。

原因：

- 桌宠是常驻应用，用户必须能控制它。
- 没有设置会让陪伴变成打扰。

最低要求：

- 显示或隐藏桌宠。
- 关闭提醒。
- 查看记忆。
- 清空记忆。

## 3. 可以删除的功能

这里的“删除”指从早期版本中删除，不代表永远不能做。

### 3.1 复杂成长等级

建议早期删除。

原因：

- 等级、阶段、解锁特质容易变成游戏化负担。
- 早期用户更需要真实陪伴，而不是数值系统。
- 如果对话体验还不稳定，成长等级没有意义。

替代方案：

- 先做简单成长日志和温和总结。
- 不做复杂等级、经验值、解锁系统。

### 3.2 复杂情绪动画

建议早期删除。

原因：

- 动画成本高。
- 容易抢占开发资源。
- 早期只需要状态可识别，不需要丰富演出。

替代方案：

- 使用少量静态状态或简单表情。
- 待机、聊天、提醒、投喂四类状态足够。

### 3.3 多格式知识投喂一次性全支持

建议早期删除“一次支持全部格式”的目标。

原因：

- PDF、Word、PPT、TXT、Markdown 的解析复杂度不同。
- 一次性全做会拖慢主线。
- 知识投喂必须配合检索、引用和管理，否则只是上传文件。

替代方案：

- 先支持 TXT 和 Markdown。
- PDF、Word、PPT 延后。

### 3.4 收入记录的早期实现

建议从 MVP 和 V1 删除。

原因：

- 收入属于敏感数据。
- 需要更强隐私设计。
- 与早期陪伴和聊天核心价值关系较弱。

替代方案：

- 在成长日志中先保留“项目进度”和“学习记录”。
- 收入记录放到更成熟版本。

### 3.5 手机版

早期删除。

原因：

- 手机版会引入跨端同步、账号系统、数据一致性和隐私问题。
- 桌宠产品的第一价值必须先在桌面端成立。

替代方案：

- 先把桌面端体验做好。
- 后续再设计手机版。

## 4. 应该延后的功能

### 4.1 语音聊天

应该延后到 V2。

原因：

- 语音能显著增强陪伴感，但技术和体验成本较高。
- TTS 音色、打断、静音、播放控制都需要细致设计。
- 文字聊天稳定之前，语音会放大体验问题。

### 4.2 完整知识投喂系统

应该延后到 V3。

原因：

- 知识投喂需要文件解析、分块、检索、引用和知识管理。
- 如果早期就做，会压缩桌宠和记忆的打磨时间。

### 4.3 周报和月报

应该延后到 V2 或 V3。

原因：

- 周报/月报需要足够数据积累才有价值。
- 早期没有稳定记录时，报表会显得空。

### 4.4 健康监督

应该延后，并保持轻量。

原因：

- 健康信息敏感。
- 健康提醒容易从陪伴变成压力。
- 不能做医疗诊断。

### 4.5 复杂长期记忆分类

应该延后。

原因：

- 七类记忆结构适合长期版本。
- MVP 只需要用户档案、偏好和目标。
- 过早引入复杂分类会增加管理成本。

## 5. MVP 版本

### 5.1 MVP 目标

验证“桌宠 + 聊天 + 基础记忆”是否能形成持续陪伴感。

MVP 不追求功能完整，只追求核心体验成立。

### 5.2 MVP 功能范围

必须包含：

- 桌宠头像。
- 点击打开聊天窗口。
- 文本聊天。
- 基础聊天记录。
- 基础 `memory.json`。
- 用户称呼和偏好记忆。
- 基础人格规则。
- 简单右键菜单。
- 隐藏或退出桌宠。

不包含：

- 语音聊天。
- 知识投喂。
- 周报月报。
- 健身记录。
- 收入记录。
- 手机版。
- 复杂成长等级。
- 多角色皮肤。

### 5.3 MVP 验收标准

- 用户能在桌面看到 Roxy。
- 用户点击 Roxy 后能聊天。
- Roxy 的语气稳定符合人格设定。
- Roxy 能记住用户确认过的称呼或偏好。
- 用户可以查看或删除基础记忆。
- 用户愿意第二天继续打开它。

### 5.4 MVP 原因

MVP 聚焦最低成本验证核心差异化：

- 桌宠提供存在感。
- 聊天提供互动。
- 记忆提供长期感。
- 人格提供角色感。

这四件事成立，RoxyPlan 才有继续扩展的意义。

## 6. V1 版本

### 6.1 V1 目标

把 MVP 从“能用”推进到“可以稳定陪伴”。

V1 应该重点完善桌面端基础体验、记忆可控性和轻量成长记录。

### 6.2 V1 功能范围

包含：

- 更稳定的桌宠状态。
- 待机、聊天、学习提醒、休息提醒基础状态。
- 完整右键菜单。
- 聊天记录管理。
- 基础长期记忆管理。
- 用户档案。
- 长期目标。
- 学习记录。
- 项目记录。
- 简单成长日志。
- 今日记录入口。
- 基础学习提醒。
- 基础休息提醒。

不包含：

- 语音聊天。
- 完整知识投喂。
- PDF、Word、PPT 解析。
- 收入记录。
- 复杂健康记录。
- 手机版。
- 复杂成长等级和解锁系统。

### 6.3 V1 验收标准

- 桌宠状态能准确反映待机、聊天和提醒。
- 用户能记录学习和项目进度。
- Roxy 能基于长期目标做轻量提醒。
- 用户能管理基础记忆。
- 产品不会频繁打扰用户。

### 6.4 V1 原因

V1 应该强化陪伴产品的日常价值。

学习记录、项目记录和轻量提醒比语音或复杂投喂更适合放在 V1，因为它们直接服务“长期成长陪伴”。

## 7. V2 版本

### 7.1 V2 目标

增强陪伴临场感和成长复盘能力。

V2 应该加入语音和更完整的成长日志，但仍不急着做完整知识库。

### 7.2 V2 功能范围

包含：

- STT 语音输入。
- TTS 语音播报。
- 语音开关和静音模式。
- 健身记录。
- 心情记录。
- 周报系统。
- 月报系统基础版。
- 成长日志页面。
- 更完善的学习监督。
- 更完善的休息提醒。

谨慎包含：

- 健康提醒只做喝水、久坐、用眼、休息。
- 心情记录默认私密。

不包含：

- 收入记录。
- 完整知识投喂。
- 手机端。
- 复杂跨端同步。
- 高级成长数值系统。

### 7.3 V2 验收标准

- 用户可以用语音和 Roxy 交流。
- 用户可以关闭语音。
- Roxy 可以生成周报。
- 月报能总结学习、项目、健身和心情趋势。
- 健康提醒保持轻量，不造成压力。

### 7.4 V2 原因

语音能明显增强“陪伴感”，但应在文字体验稳定后加入。  
周报和月报需要 V1 的记录数据支撑，所以放到 V2 更合理。

## 8. V3 版本

### 8.1 V3 目标

让 Roxy 从陪伴型 AI 进化为个人知识伙伴。

V3 的重点是知识投喂和检索引用。

### 8.2 V3 功能范围

包含：

- TXT 投喂。
- Markdown 投喂。
- PDF 投喂。
- Word 投喂。
- PPT 投喂。
- 文件解析状态。
- 知识提取。
- 知识库存储。
- 基础检索。
- 对话中引用知识来源。
- 知识库管理页面。
- 投喂状态桌宠反馈。

可以包含：

- 收入记录基础版。
- 项目与知识文件绑定。
- 月报中加入收入和知识使用情况。

不包含：

- 手机版。
- 多端同步。
- 复杂自动化工作流。
- 高级知识图谱。

### 8.3 V3 验收标准

- 用户可以投喂五类文件。
- Roxy 能基于投喂内容回答问题。
- 回答能说明来源。
- 用户能删除或禁用资料。
- 投喂资料不会自动进入长期记忆。

### 8.4 V3 原因

知识投喂是 RoxyPlan 的大能力，但必须建立在稳定聊天、记忆和成长记录之后。  
否则用户即使上传了资料，也不会感到它真的在陪自己成长。

## 9. 功能优先级总表

### 9.1 必须优先

- 桌宠入口
- 文本聊天
- 基础人格
- 基础聊天记录
- 基础长期记忆
- 基础设置
- 记忆查看和删除

### 9.2 可以删除或砍掉早期范围

- 复杂成长等级
- 复杂动画
- 多皮肤
- 一次性全格式知识投喂
- 早期收入记录
- 早期手机版
- 高级知识图谱

### 9.3 应该延后

- 语音聊天
- 周报月报
- 健身和心情趋势
- 完整知识投喂
- 收入记录
- 手机版
- 跨端同步

## 10. 推荐路线

推荐版本路线：

1. MVP：桌宠 + 聊天 + 基础记忆。
2. V1：稳定陪伴 + 学习/项目记录 + 轻量提醒。
3. V2：语音 + 健身/心情 + 周报/月报。
4. V3：知识投喂 + 检索引用 + 知识库管理。

这条路线的好处：

- 先验证核心陪伴感。
- 再验证成长记录是否有用。
- 然后增强语音临场感。
- 最后加入复杂知识系统。

## 11. 产品判断

RoxyPlan 最容易失败的风险不是功能少，而是功能太多、主线不清。

早期必须守住一句话：

“Roxy 是一个能长期陪我成长的桌面 AI 伙伴。”

所有功能都应该服务这句话。

如果某个功能不能增强“长期陪伴”“成长记录”“个人理解”这三件事，就应该删除或延后。

## 总结

MVP 不应该做成完整系统，而应该做成一个让用户愿意留下来的小 Roxy。

V1 让它稳定陪伴。  
V2 让它更有临场感并能复盘成长。  
V3 让它理解用户资料，成为个人知识伙伴。

这样 RoxyPlan 才能从一个可爱的桌宠，逐步成长为真正长期陪伴用户从 22 岁走向毕业的 AI 伙伴。

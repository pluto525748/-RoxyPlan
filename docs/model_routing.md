# Model Routing

## 三种模式

| 模式 | 默认行为 | 复杂任务 |
| --- | --- | --- |
| 省钱 | 使用 `default_model` | 不自动升级 |
| 自动 | 使用 `default_model` | 工具执行前可升级一次 `complex_model` |
| 高质量 | 优先 `complex_model` | 仍由本地规则直接处理明确低成本命令 |

模型路由集中在 `ModelRouter`。UI、GrowthManager、MemoryManager 和 Web 路由不自行选择模型。

## 决策输入

- 当前意图。
- 是否有多个动作或多个工具。
- 是否包含复杂指代。
- 是否处理记忆冲突。
- 是否为长复盘或深度规划。
- 第一次结构化解析是否失败。
- 用户模式、Key 状态和 Provider 可用性。

## 分层顺序

1. 固定命令和高置信本地规则直接交给 AgentCore，不调用模型。
2. 普通聊天和简单语义使用默认模型。
3. 复杂指代、多动作、记忆冲突和长复盘在自动模式下使用复杂模型。
4. DeepSeek 不可用时，普通聊天降级本地 Ollama。
5. 两个 Provider 都不可用时明确失败。

## 思考模式

- 普通聊天：默认非思考。
- 普通 Tool Calling：非思考优先。
- 复杂多动作：复杂模型非思考优先。
- 深度规划、记忆冲突分析、长复盘：可启用思考。
- 用户可以在设置中关闭全部复杂任务思考。

思考内容不是最终答案，不展示、不写入会话摘要和普通历史。工具循环中只有 DeepSeek 协议要求时，才在同一请求链中临时回传。

## 自动升级边界

- 每轮最多升级一次。
- 只允许在任何工具执行之前升级。
- 已执行写工具后不再“换模型重新理解”。
- 复杂模型仍失败时停止循环并返回受控错误或本地普通聊天降级。
- 参数错误、高风险目标不由模型反复猜测，进入澄清或确认。

## 本地降级边界

Ollama 用于断网或在线服务异常时的基础问答。固定命令仍可由本地规则和 AgentCore 正常执行。Ollama 不负责模糊写操作，也不能绕过 ToolExecutor 或高风险确认。

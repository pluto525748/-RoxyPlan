# Agent Execution Budget

RoxyPlan 的模型工具循环采用集中、保守的默认预算：

| 项目 | 默认值 | 行为 |
| --- | ---: | --- |
| 模型工具回环 | 2 | 超出后使用已有真实结果结束 |
| 单轮工具调用 | 3 | 超出时在执行前安全终止 |
| 参数修复 | 1 | 第二次仍失败时转用户澄清 |
| 写操作并行 | 0 | 始终按顺序执行 |

## 终止条件

- 工具名未知或未开放。
- 参数在一次修复后仍无效。
- 高风险工具参数不明确。
- 同一轮重复出现相同 `call_id`。
- 工具调用总数超过预算。
- 关键写操作失败。
- SafetyPolicy 要求确认或拒绝。

## 幂等边界

`ToolExecutor` 在当前进程内缓存已成功的 `tool_call_id`。同一调用 ID 再次出现时返回原 `ToolResult`，不再次写入。本地 JSON 自身仍使用 Repository 的锁、临时文件和原子替换；当前没有跨机器或数据库级幂等保证。

## 参数修复

低、中风险且仅为 schema 错误的提案可收到一条去敏 ToolMessage。修复后的工具名和参数必须重新经过白名单、schema、SafetyPolicy 和确认流程。安全策略细节、私人数据和本地路径不会提供给模型。

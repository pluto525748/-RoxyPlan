# RoxyPlan 能力边界与交互约定

更新时间：2026-09-24
适用范围：V0.9 本地原型中的 V2.2 中文交互与成长闭环稳定化。

本文件是当前产品范围与推荐交互方式的维护契约，不是“任意中文都能理解”的承诺，也不代表所有场景已验收通过。实际完成度、已知缺陷和带日期的验证结果见 [current_status.md](current_status.md)。上线时可据此整理简明操作说明；在发布之前，不把本文直接当成已经验收的用户手册。

## 1. 用户表达约定与程序责任

推荐使用“操作目的 + 明确对象 + 日期范围”的完整自然句，一轮优先处理一类操作。时段和时长有需要时再补充，不要求每条计划都带时长。用户不需要知道内部工具名、稳定 ID、参数键或 JSON，也不需要背诵唯一句式。

以下建议用于减少歧义，而不是免责条款：

- 要新增计划，说明今天打算做什么；要记录行动，说明已经实际做了什么。
- 要保存长期信息，明确说“记住：……”。普通闲聊可以正常进行，不必写成命令。
- 确认前核对程序展示的操作和对象，推荐回答“确认”或“取消”；需要改对象时，用完整的新请求说明。
- 短回答、序号和“这个／全部”只适用于当前会话中真实展示、尚有效的对象或正在等待回答的操作。跨会话、隔太久、对象失效时，优先重新查询并说完整标题。
- 多个不同操作拆成几轮，例如先新增，再完成；程序不能把不明确的混合请求拆成未经同意的写入。

程序始终负责：否定不误执行、目标不能猜错、确认前不写入、工具失败不声称成功、重复操作不重复记账、有界澄清后诚实退出。完整且属于已支持范围的请求执行错误，仍是程序缺陷。

澄清时推荐只回答当前所问的信息：问事项就答“英语阅读”，问时长就答“30 分钟”，问选择就答“第二项加入今天计划”，展示最终操作预览后再答“确认”。用户也可以直接重说完整请求；程序须区分新请求与旧操作续接。“好／都行／全部”等短答只有当前待处理操作和范围明确时才能使用，程序不能据此猜测另一类操作。

## 2. 状态口径

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 核心保留 | 已确认必须保留的能力与交互契约 | 明确故障补回归并修程序，不事后缩减承诺 |
| 已知缺陷 | 在已支持范围内有真实失败证据 | 记录故障链、最小修复与验证状态，推荐句仅作临时绕行 |
| 降级 | 有兼容或局部路径，但不开放任意自然语言规划 | 先尝试已支持的可靠入口；不可完成就说明限制 |
| 暂缓 | 已确认的需求或改善，用户决定本阶段不处理 | 明确保留待办，不写成已修复或未设计 |
| 未设计 | 没有获准的能力与执行路径 | 不建立假确认流程，不借修 bug 新增功能 |

“底层存在 handler”“旧测试曾通过”“模型说可以做”都不等于当前模型可调用或用户可依赖。执行策略与可见性由 [CapabilityRegistry](../modules/capability_registry.py) 管理，参数、别名及 handler 由 [ToolRegistry](../modules/tool_registry.py) 管理。本文只描述用户契约，不再复制一份 schema 或白名单。

## 3. 核心能力及推荐表达

表中的“必要信息”是用户应表达的语义信息，不是内部参数名。

| 能力 | 必要信息／可选信息 | 完整推荐表达 | 回答与确认约定 |
| --- | --- | --- | --- |
| 普通聊天、能力询问、学习建议 | 当前话题或建议目的；可补限制与偏好 | “我是新用户，介绍一下你现在能做什么。”／“不要展示计划，建议我先做什么。” | 介绍或建议不等于执行，不自动读取整份记忆或新增计划 |
| 新增今日计划 | 具体事项；可补日期、时段、时长 | “今天加一项计划：英语阅读。”／“今晚安排简历整理，30 分钟。” | 明确完整的单项可执行；缺对象只问对象，不能转成计时或建议选择 |
| 后续继续新增 | 新事项或有效建议列表中的选择；可补时间 | “再加一项今天的计划：复习 Python。”／“第二个也加入今天计划。” | 第二项续选属于保留能力；第一项成功后不能丢掉原建议列表 |
| 批量新增（直接陈述） | 每项明确事项与共同日期范围 | “今天加入三项计划：英语阅读、整理简历、复习 Python。” | 模型临时生成且尚未核验的自由多动作仍限制为最多三项；超限提示拆分，不静默只添加首项 |
| 已展示建议整批新增 | 当前会话、当日有效的编号建议列表 | 展示后“把你说的加入今日计划。”／“把刚才四项全部加入今日计划。”／“剩下的都加入。” | 没有序号或单项指代时，“你说的／这些安排”默认指完整未消费列表；对完整快照一次预检并在一轮内处理，正常列表不要求用户手动拆批；有重复时整批先零写入，只统一询问一次“添加未重复项／仍然全部添加／取消” |
| 查询计划 | 日期范围；省略时按今日入口 | “查看今天的计划。”／“查看昨天的计划。”随后“今天的呢？” | 当前句明确日期优先；真实列表保留展示顺序与稳定对象绑定 |
| 完成单项计划 | 明确标题或有效展示引用 | “把今天的英语阅读标记完成。”／展示后“第一项已经完成了。” | 只更新绑定目标；已完成项说明无需重复，不自动改记计划外行动 |
| 完成多项／展示集合 | 明确范围或有效列表中的多项 | “把今天所有未完成计划标记完成。”／展示后“刚才展示的都完成了。” | 先展示真实目标并统一确认一次；“确认／全部”等回答不得转入新增流程 |
| 记录实际行动 | 已发生的具体事情；可补日期 | “记录今天的计划外行动：学会了一道菜。” | 计划外行动与计划分开；提议记录时必须有真实待确认操作，成功后才说已记录 |
| 今日复盘与保存 | 查看或保存目的；修订时明确日期 | “查看今日复盘。”／“生成并保存今天的复盘。”／“重新生成昨天的复盘。” | 只读预览不冒充已保存；明确保存或重生成才写指定日期 |
| 自然月成长日志与总结 | 本月或明确自然月；可提出总结目的 | “查看本月成长日志。”／“查看 2026 年 8 月的成长日志。” | 按自然月返回统计和每日记录；已支持总结路径只使用核验数据，模型失败返回确定性统计 |
| 长期记忆与长期目标 | 明确保存内容或读取目的；可限定主题或正式类别 | “记住：我喜欢清淡饮食。”／“记住：我的长期目标是提高英语。”／“我叫什么？”／“看看项目记忆。”／“你了解我什么？”／“把你知道的关于我的全部信息都告诉我。” | 明确保存可走正式记忆工具；项目、目标、偏好、习惯等明确类别进入同一类型化读取；具体属性只读取相关真实事实；宽泛了解把全部有效正式事实作为核验证据交给现有模型自然组织，明确要求全部时逐条覆盖 |
| 删除单条长期记忆 | 唯一正式记录的完整正文 | “忘记：我喜欢清淡饮食”随后“确认”或“取消” | 仅支持该精确命令；匹配全文并展示真实目标，一次确认后删除；正文不一致、重复或目标变化均停止 |
| 旧会话联系与查询 | 当前话题或查询线索 | “之前我们聊过简历吗？” | 普通聊天优先自然衔接最多两条高相关真实旧片段；明确查询只返回最相关一至两个片段及日期、来源，没有证据就说未找到 |
| 桌宠、聊天、设置和成长面板 | 对应界面或既有动作 | “来段舞。”／“休息一下。” | 保留现有入口与动作；不能执行的客户端不冒充播放成功，后续聊天不否认已存在的能力 |

洛琪希回答“你能做什么”“这个功能怎么用”“我不知道怎样删除计划／记忆”时，必须依据运行时 [CapabilityRegistry](../modules/capability_registry.py) 生成的当前操作说明，不凭模型常识猜入口。能力询问只说明步骤，不执行工具、不建立待确认操作，也不读取无关私人数据。宽泛介绍可由现有模型自然组织；涉及高风险或严格格式的入口采用确定性说明，例如计划删除为“查看今天计划”→“删除第2条／完整标题”→“确认”，长期记忆删除为查看准确原文→“忘记：完整记忆正文”→“确认”。未支持或降级能力要同时说明限制与真实替代路径，不编造命令。

“按记忆理解我”和“列出我的长期记忆”目的不同。具体属性问题只向现有模型提供对应事实；“你了解我什么”一类宽泛问题会把当前全部有效正式事实作为已核验证据提供给模型，由模型结合本轮语气自主选择详略和组织方式，不再在输入层硬截成三四条；“全部／所有／完整／逐条”则要求最终回答覆盖每条事实。模型回答必须返回实际引用的记忆 ID 并通过本地事实校验，失败可重试一次，仍失败才使用确定性本地回复。没有记录只说明未找到相应正式信息，不能据此断言用户从未说过。

候选记忆已退出用户交互，不是正式记忆的别名。用户在聊天中提出“查看待审核记忆”“确认候选1”“清空待确认记忆”等旧候选请求时，程序零工具、零写入并明确说明该能力已停用，引导改用“记住：完整内容”或“查看长期记忆”；不得偷偷改成正式记忆读取或写入。旧候选的数据结构、服务和确定性 API 仅为内部兼容保留，不出现在模型可见能力、桌面记忆页、设置项或 Local Web 页面中。

## 4. 快捷引用与确认的边界

序号、“第二个也加入”、指定标题和“刚才展示的都完成了”是已确认的 V2.2 核心交互，不因真实测试失败而自动降为不支持。用户推荐完整标题；程序仍须维护已承诺的快捷路径。

- 计划序号依据用户实际看到的成功查询快照，不按后来增删后的实时下标重绑。当前句具体标题优先于标题内部的“一个／第二个”等数量字样。
- 建议列表必须是与程序可解析结构匹配的单层编号列表，每项为明确可执行事项。选择“全部／剩余项”，或在没有序号、标题和单项指代时说“把你说的／把这些安排加入今日计划”，应保留原集合和原操作类型；无法整批处理就说明范围，不替用户缩成一项。
- 生成建议时必须遵守用户已经给出的日期、时间范围、时长和主题。合法列表先进入 `assistant_plan_offer`：用户可以直接选择、要求全部加入，也可以用“学习一点／轻松一点／还是安排到十一点后”等短句补充一次条件。补充只会携带原始约束重新生成建议，零工具、零写入；新列表进入 `assistant_plan_selection`，不再循环追问。信息已经足够时不强制细化；是否自然邀请用户补充、具体怎么说，由模型结合上下文生成，本地程序不得拼接固定引导话术，也不得把补充变成执行前置条件。“算了／不用了”后紧接完整的正向加入命令时按后半句处理，纯否定仍零写入。
- 当前存在有效建议列表时，用户询问“应该怎么说／怎么表达”应直接获得可执行说明，例如“把你说的全部加入今日计划”或“把第二项加入今日计划”；操作说明本身不触发工具，也不能被回复真实性保护误判为已经执行。
- 已展示且通过结构校验的建议快照不受模型自由多动作三项上限约束；“全部加入”消费该快照中的全部未处理项。跨会话、跨日、过期、数量不符、异常列表或对象变化时零写入并给出重新获取建议的表达。
- 可执行建议仅保留当前会话、当日有效的真实展示顺序；第一项真实加入成功后，原编号第二项仍可续加。保存建议快照不等于自动新增计划，普通闲聊不得被选择流程接管。
- 只有用户明确要求“今日计划建议／候选／安排”，或从类型化“现在开始／听建议／加入今日计划”选择中取得建议后，程序实际展示并通过结构校验的列表，才保证支持“第几个／全部加入／把你说的加入今日计划”等快捷引用。普通聊天中偶然出现的步骤、旅行准备或知识讲解列表不建立可执行快照；此时同样的整体指代应零写入并明确引导用户改说“今天加入三项计划：事项一、事项二、事项三”，或先重新请求“给我几项今日计划建议”。
- 一次只存在一个带明确能力类型的待处理操作。确认短答只续接该操作，不能被新增计划、学习时长或记忆流程接管。
- 写入前重新核验真实对象；对象已删除、状态改变或引用失效时安全停止，不能改到其他对象。
- 同一待处理操作最多澄清两轮。仍无法确定时取消并给出完整可执行示例；“取消”后不继续执行旧操作。

### 从自然表达进入计划执行的完整边界

- 用户明确列出多项并要求加入今日计划时，当前整句应交给语义链识别，不能先被本地单计划入口截成一项或两项。例如“今天加入三项计划：A、B、C”和“我今天要做三件事：A、B、C，请都加进计划”都应逐项形成经过 schema 校验的 `add_plan` 动作；任何数量上限都必须在写入前明确说明，不能静默截断后宣称全部成功。未经核验、由模型自由生成的多动作仍遵守三项安全上限；程序已经真实展示并保存的有效建议快照可按“全部加入今日计划”消费完整列表。
- “给我四项今日计划建议，先只给建议，不要加入计划”属于零写入的建议请求。回复中实际展示的单层编号列表通过结构校验后，才可成为当前会话、当日有效的建议快照。
- “能把你说的加入今日计划吗”是礼貌询问，不单独视为立即写入许可。存在有效建议快照时，应完整重显原列表并请用户说“第一个”“1、2、3”或“全部加入今日计划”；不得重新生成后缩短原列表，也不得串入学习时长等其他流程。没有有效快照时零写入，并引导用户先请求计划建议或直接说“今天加入三项计划：事项一、事项二、事项三”。
- “本轮没有注入到相关记忆”不等于“正式记忆为空”。只有当前轮成功完成正式记忆读取且结果为空，才能作出全局为空的结论；“我叫什么”“我的长期目标是什么”等属性问题应读取并只回答相关的正式事实。
- 询问删除记忆能力时，应明确告知唯一受支持的路径：“忘记：完整正文”→展示匹配目标→用户确认或取消。缺少冒号、正文不完整或使用宽泛的“删除这条记忆”时不得删除，应给出这条完整表达，而不是进入循环确认或宣称没有记忆。

状态与快照细节见 [interaction_state_machine.md](interaction_state_machine.md)。

## 5. 计划、行动、成长与记忆必须分离

- “今天背英语单词”是今日计划；“我长期想提高英语”是长期目标记忆。长期记忆可以辅助定制建议或计划，不能自动创建今日计划。
- 计划、行动和复盘不能自动转成长期记忆。普通稳定、非敏感信息如适合保存，只提出具体内容并询问；确认前仅存当前进程状态，不写正式记忆或候选文件。
- 敏感信息不主动建议保存，原则上只接受用户明确的保存请求。
- `temporary_state` 记录保留数据兼容，但退出当前工作检索、问候和上下文；不借此删除或迁移用户旧数据。
- 记忆使用状态只在最终回答确实引用相应事实后更新：模型自然回答使用通过本地校验的实际引用 ID，本地兜底使用正文核验；不能把上下文注入当作使用。
- 计划外真实进展在复盘中列为“计划外行动”。计划数、完成数、行动数、记录日与连续日是不同事实，不用自然语言总结混为一谈。
- 旧会话片段提供连续性，不成为正式记忆，不触发计划写入，也不根据当前对话编造旧内容。

启动时自动补全昨日复盘的设置默认开启，与晚间提醒独立。每次启动只检查昨天：空日不保存，已有日志完全不变，有数据且无日志时本地保存完整核验快照，不调用模型。成功静默；普通失败先写诊断，连续失败或数据损坏才提示。用户明确要求重生成才修订已有日期。细节见 [growth_system.md](growth_system.md)、[memory_system.md](memory_system.md) 和 [chat_history_system.md](chat_history_system.md)。

## 6. 降级、暂缓与未设计范围

- 开始学习、计时，以及复杂修改、合并、改期、重排等不是本阶段核心自然语言承诺。保留既有可靠本地／兼容路径，不开放模型任意规划，也不新增实现。
- 显式、唯一单项删除可保留已存在的本地绑定与一次确认路径，不等于开放模型删除工具；推荐先“查看今天计划”，再说“删除第2条”并确认。“删除全部计划”不因本轮测试而新增支持，应零删除并明确引导用户逐条处理；无法建立真实可执行操作时直接退出，不能反复问确认。

# 对话历史与上下文连续性

RoxyPlan V1.0 使用本地 JSON 保存最近对话，并通过会话摘要和消息裁剪维持上下文连续性。该系统仍是桌面原型能力，不是云端聊天服务。

## 已实现

- 按 session 保存用户、Roxy 和系统消息。
- 启动聊天窗口时可恢复最近一次会话。
- 支持新建、查看、切换和删除本地会话。
- “清空聊天记录”需要再次输入“确认清空聊天记录”。
- 新会话达到 3 条消息后，使用第一条用户消息生成简短标题。
- 会话超过 30 条消息或字符阈值时生成规则摘要。
- 普通模型请求默认只使用最近 16 条上下文消息。
- 设置面板可关闭新消息保存、关闭启动恢复、调整上下文数量或关闭自动摘要。

## 本地数据

- `data/private/chat_history.json`：会话元数据和聊天消息。
- `data/private/chat_summaries.json`：会话摘要和摘要对应的消息数量。
- `data/private/` 已加入 `.gitignore`，不应提交到公开仓库。

关闭“保存聊天历史”后，程序不再写入新消息，但不会自动删除已有记录。删除单个会话或清空全部历史属于显式隐私操作。

## 上下文顺序

发送普通聊天请求时，`ContextBuilder` 按以下顺序组装上下文：

1. Roxy 人格和回复约束。
2. 与当前输入相关的已确认长期记忆，普通聊天最多 5 条。
3. 当前会话摘要。
4. 最近指定数量的聊天消息。
5. 与当前问题匹配的本地知识片段。
6. 当前用户输入。

全部历史和全部长期记忆都不会一次性发送给模型，当前用户输入也不会重复注入。自然表达“你都记住了我的什么信息”“你了解我什么”等会直接走本地记忆查看，不依赖模型回答。健康和关系类记忆只有在当前问题明显相关时才会注入；会话摘要、用户消息和助手回复中的无关敏感话题都会逐轮过滤，不会因上一轮出现而持续黏附。今日计划、行动记录和成长日志仍由 `GrowthManager` 管理，不会默认塞入普通聊天上下文。

## 摘要与长期记忆

会话摘要用于压缩当前会话，内容包括主要讨论、明确决定、当前状态、未完成事项和下次可继续的上下文。当前实现使用稳定的本地规则摘要，避免额外阻塞聊天线程。

会话摘要不等于长期记忆：

- 摘要只保存在 `chat_summaries.json`。
- 摘要不会自动写入 `memory.json`。
- 长期记忆仍需用户明确要求，或对记忆候选进行确认。

## 聊天命令

```text
新建对话
查看历史对话
切换对话1
删除对话1
总结这段对话
清空聊天记录
确认清空聊天记录
```

聊天窗口顶部也提供“新对话”和“历史”按钮，历史面板可以打开或删除指定会话。

“你记得刚才说什么”由当前 `conversation_id` 的最近消息确定性回答；“以前聊过什么”返回本地会话标题、更新时间和消息数量，不会声称从未保存过已经存在的会话。等待确认属于运行时状态，服务或桌面进程重启后不会恢复。

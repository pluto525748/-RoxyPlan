# 对话历史与上下文连续性

每日学习会话另保留有界的只读成长参考：即使用户用状态描述或省略表达，也按当前实例业务日期纳入近期计划、行动与已保存复盘，避免只有命中学习关键词才有历史依据。完整学习对话检索仍沿原相关性和预算，普通手动会话及摘要不增加该基线；已有记录不必反问用户重述，闲聊不强行转学习，参考不授予任何写入权限。

RoxyPlan 使用本地 JSON 保存最近对话，并通过会话摘要、消息裁剪和轻量模糊检索维持上下文连续性。该系统仍是桌面原型能力，不是云端聊天服务，也不依赖向量数据库或云端历史库。

## 已实现

- 按 session 保存用户、Roxy 和系统消息。
- 开启聊天历史保存时，聊天窗口初次打开、同日隐藏后重开及重启均选取业务日期对应的唯一默认学习会话；发送前再次核对日期，过日则先切换当天会话再记录用户消息。
- 历史窗口和“切换对话N”仅供只读回看；回看时禁用输入与发送，标题标出日期，点击“返回今天”继续当天会话。浏览不会改写历史消息或更新时间。
- 聊天顶部与历史列表将带业务日期的每日会话展示为“魔法修行日记 · YYYY-MM-DD”；只读回看另标“历史对话 · 只读”。这是展示名称，存储标题、消息、日期和会话 ID 保持原值；旧手动会话仍使用原有标题。
- 聊天界面不再提供用户新建、删除、清空或改名会话的入口；底层 `new_session` 等能力保留供兼容与内部调用。既有手动会话和缺少业务日期的旧会话原样保留为历史，不自动归日。
- 每日默认会话由 `ChatHistoryManager.ensure_daily_learning_session(business_date)` 依据明确传入的业务日期查找或创建；同日多条明确标记记录会报冲突，不任意选取。读取或保存失败时聊天不可用，可点“返回今天”重试，不退回昨日会话。
- `restore_last_session` 旧配置值仍被读取和保留，但不再决定桌面聊天选取哪个会话，设置界面不再展示与每日规则冲突的开关。`chat_history_enabled=false` 时同一进程按日复用临时会话与消息，不写聊天历史；退出程序后无法恢复这段临时聊天。
- 单次请求提交时固定会话 ID、业务日期与 trace；等待期间即使切换到历史只读视图，回复仍归原会话。空闲窗口午夜主动切换尚未实现，隐藏后重开或再次发送才检查日期。
- 独立模拟跨天入口 `scripts/run_simulated_days.ps1` 要求仓库外绝对 `InstanceRoot`。首次用 `-StartDate YYYY-MM-DD`，随后同一根重启省略该参数；窗口仅在此模式显示“当前测试日期”和“推进一天”。推进前拒绝运行中的请求，换日后选取当天会话、清除旧确认与选择状态，未发送输入保留。测试日期只存于隔离根的 `simulation_state.json`；正式启动不读取该标记。
- 模拟日期下，每日会话的历史日期与摘要时间关系优先使用显式 `business_date`；消息的真实 `created_at` 仍保存实际发生时刻。旧手动会话缺少业务日期时继续依真实消息时间解释，不猜测归日。
- 新会话达到 3 条消息后，使用第一条用户消息生成简短标题。
- 会话超过 30 条消息或字符阈值时生成规则摘要。
- 普通模型请求默认只使用最近 16 条上下文消息。
- 设置面板可关闭新消息保存、调整上下文数量或关闭自动摘要；旧 `restore_last_session` 值保留但不再影响每日会话选择。
- 对“查看本月以前聊过的某个主题”等自然查询做本地轻量模糊检索，只返回匹配到的旧会话摘要、片段、日期或来源，并排除当前会话。
- 没有匹配证据时明确回复没有找到，不根据当前对话或模型推测编造旧会话内容。
- 普通聊天也可在后台检索旧摘要以增强连续性，但最多只选两条与当前句直接相关的真实片段；只共享“学习”“工作”等泛化词时不召回，普通问候无证据时静默跳过。
- 隐式衔接时当前用户表达优先，模型不得机械复述摘要；日期、会话编号和来源标签默认只作为内部证据，只有用户明确询问旧会话或出处时才展示。
- 2026-10-27 学习上下文：共享会话在学习建议／讲解和已有学习前文的连续短追问中读取真实旧问答，短会话不必先有摘要。最近三个已过去业务日（及其他旧会话的当日片段）复用现有学习语境判断：明确学习锚点与连续追问不要求与本轮重复同词；需保留追问的原锚点及中间问答，转题、无关闲聊或任一角色敏感内容切断该连续段。第4～7日及更早片段继续使用既有主题匹配。最近七日按日期轮选并预留字符／组数给能容纳的其他日期，每轮仅补一个更早的主题匹配；不保证预算不足时每个日期均可纳入。
- 学习历史问答默认预算为序列化投影合计18000字符（含来源与覆盖元数据），至多24组原问答；超长问答整组省略，不切正文或拼接角色。保留原role／正文／created_at、会话、业务日期、原消息位置、锚点及入选原因，分别报告词面匹配数、可用／纳入／省略组数和逐日覆盖。逐日元数据保留最近31个候选日期及所有实际入选日期，其余日期数量明确披露；极小自定义预算连元数据也容纳不了时报告metadata_over_budget。只读当前历史仓库，不搜索其他实例目录；同时按现有会话／摘要persona标识过滤，排除当前会话。每日会话按business_date、旧跨日会话逐条按created_at判断并排除未来，跨日助手回复不拼进旧日用户问答。没有真实相关片段时不补造。
- 成长投影（默认约26000字符）、有效画像（7000字符）与历史问答在共享ContextBuilder中共同核算，学习参考总窗口48000字符须先扣除必保留系统／安全／已核验工具事实、本轮输入及已有近期对话。学习画像不再另作普通记忆重复注入；压力下先省略更早成长材料、兼容简表和第4日以后的问答，再裁较早成长记录／画像，最近困难和今天事实优先。按完整记录／问答及原保存文本字段裁减，更新省略计数与context_budget诊断，不切JSON。若单是硬性系统和当前对话已超窗口，保留这些原有硬要求并记录hard_context_overflow；学习参考无法完整序列化时整体省略并报告reference_omitted，不假装空历史。这是明确剩余边界，字符预算不等于provider token限制。
- 学习衔接从当前输入和最近真实用户轮判断，连续“只有20分钟／再短一点／换个例子”等可承接学习前文；明确换话题或无关问题停止新增学习投影，不改变原有工具路由。无关敏感旧片段不纳入。指代仍不唯一时应有界澄清，不猜测学习点。请求中提供实际注入大小、历史覆盖和缺失；该注入不证明模型一定正确理解或教学内容正确。

## 本地数据

- `data/private/chat_history.json`：会话元数据和聊天消息。
- `data/private/chat_summaries.json`：会话摘要和摘要对应的消息数量。
- `data/private/` 已加入 `.gitignore`，不应提交到公开仓库。

关闭“保存聊天历史”后，程序不再写入新消息，但不会自动删除已有记录。设置中的“清空本地聊天历史”仍是独立的显式隐私操作；聊天界面不提供清空或单会话删除。

2026-09-18 起，桌面入口默认保存独立的最小开发事件。开启时，仅本次新消息的 metadata 增加 run/trace ID，用于关联对应语义、工具和显示证据；旧记录不迁移，关闭历史保存也不会因此重新写入聊天正文。按钮与启动补齐有独立来源，不能算成聊天成功。开发日志不复制完整控制台或模型正文；详细 diagnostics 仍服从原开关。目录、保留、关闭方式和只读排查见 [开发日志说明](development_logging.md)。

## 上下文顺序

发送普通聊天请求时，`ContextBuilder` 按以下顺序组装上下文：

1. Roxy 人格和回复约束。
2. 与当前输入相关的已确认长期记忆，普通聊天最多 5 条。
3. 当前会话摘要。
4. 与当前句高相关的最多两条旧会话片段（没有可靠匹配时省略）。
5. 最近指定数量的聊天消息。
6. 与当前问题匹配的本地知识片段。
7. 当前用户输入。

全部历史和全部长期记忆都不会一次性发送给模型，当前用户输入也不会重复注入。自然表达“你都记住了我的什么信息”“你了解我什么”等会直接走本地记忆查看，不依赖模型回答。健康和关系类记忆只有在当前问题明显相关时才会注入；会话摘要、用户消息和助手回复中的无关敏感话题都会逐轮过滤，不会因上一轮出现而持续黏附。今日计划、行动记录和成长日志仍由 `GrowthManager` 管理；只在上述学习范围组装有界只读投影，不默认塞入无关闲聊。

## 摘要与长期记忆

会话摘要用于压缩当前会话，内容包括主要讨论、明确决定、当前状态、未完成事项和下次可继续的上下文。当前实现使用稳定的本地规则摘要，避免额外阻塞聊天线程。

会话摘要和隐式检索片段都不等于长期记忆：

- 摘要只保存在 `chat_summaries.json`。
- 摘要不会自动写入 `memory.json`。
- 旧片段只作为当前回复的只读背景，不会自动创建长期记忆、今日计划或行动记录。
- 显式且内容完整的“记住……”可走正式记忆工具；普通对话中的稳定信息必须先提出具体保存建议并获得确认，确认前不写正式记忆或磁盘候选。

## 聊天命令

```text
查看历史对话
查看本月成长相关的旧会话
我们以前聊过英语学习吗
切换对话1
总结这段对话
```

聊天窗口顶部提供“历史”按钮，历史面板只能打开旧会话回看。只读回看时顶部出现“返回今天”；“新建对话”、聊天中的删除／清空命令不会创建或删除会话。

“你记得刚才说什么”由当前 `conversation_id` 的最近消息确定性回答；“以前聊过什么”返回本地旧会话标题、时间、摘要或片段，“以前聊过某主题吗”会按查询词做轻量模糊匹配。结果必须来自真实已保存旧会话，当前会话不作为旧历史证据；没有匹配时明确说没有找到。等待确认属于运行时状态，服务或桌面进程重启后不会恢复。

# V1.8 确认策略

确认策略只读取 `ToolRegistry` 的统一元数据：`side_effect`、`risk_level`、`confirmation_policy` 和 `reversible`。Planner 和模型不能自行降低或额外发明确认要求。

## 策略

- `never`：只读查询、`play_dance`、候选接受/忽略、可逆归档/恢复等直接执行。
- `when_ambiguous`：普通计划添加、行动记录、更新或完成在语义明确、目标唯一且参数完整时直接执行；低置信模型提议需要确认，目标不唯一进入选择，缺参数进入澄清。
- `always`：删除计划、删除记忆、更新正式记忆、高风险冲突处理和全量删除始终二次确认。

缺字段不是确认，多候选也不是确认。确认只绑定已经确定的工具、不可变参数、会话和目标状态；超时、重启或目标变化后必须重新发起。候选审核本身就是用户明确选择，不再叠加通用二次确认。

# RoxyPlan 智能记忆系统

## 当前范围

V1.7.3-A 延续人工治理链路，并用统一 `MemoryService` 连接桌面记忆面板、聊天 Agent 和 Local Web 适配器。候选生成、审核、冲突处理和审计完成后，内容才可能成为正式长期记忆。

## 统一业务入口

`MemoryService` 不保存第二份数据。它组合现有 `MemoryManager`、`MemoryCandidateManager`、`MemoryGovernanceService` 和同一个 `MemoryRepository`，并返回不会是 `None` 的 `MemoryOperationResult`。

`MemoryDataQueryGuard` 在普通聊天前识别记忆数据查询。候选列表成功后，`ConversationStateManager` 只在当前会话、有限时间内保存真实候选 ID；“第二个”“这两个”等表达由 `ReferenceResolver` 绑定这些 ID。候选引用状态与删除等危险操作的 `PendingConfirmation` 相互独立。

- 面板按钮通过服务执行确认、忽略、编辑、归档、恢复、删除和冲突处理。
- Agent 的正式记忆工具只调用服务，不直接读写 JSON。
- Local Web 适配器使用同一服务，同时保留原 API 的兼容返回结构。
- `conversation_id` 只标识聊天会话；切换会话不会改变长期记忆、候选、冲突、Repository 或数据根目录。
- 现有 Repository 继续负责原子替换和本机轻量锁，真实 JSON 格式没有变化。

## 长期记忆结构

`MemoryManager` 兼容旧 `memory.json`。检测到旧结构时，会先把原文件完整备份到 `data/private/backups/memory_时间戳.json`，再原子写入新结构。备份失败时不会覆盖原文件。

每条长期记忆包含 ID、内容、类别、创建/更新时间、重要度、最近使用时间、使用次数、状态、来源和标签。支持类别：偏好、目标、习惯、项目、学习、健康、重要关系、明确规则和其他。

可选时空字段包括 `scope`、`location`、`valid_from`、`valid_until`、`last_confirmed_at`、`supersedes` 和 `contradicted_by`。作用域支持：当前状态、稳定身份、历史状态、未来意向、偏好、临时状态和持续约束。旧数据缺少这些字段时只在运行时补默认值，不因普通加载强制改写私人文件。

### 明确记忆

用户明确输入下列形式时，内容进入高置信候选，不直接写入长期记忆：

- `记住：我喜欢安静的学习环境`
- `帮我记住我周末适合整理项目`

候选仍需用户确认。完全重复或高度相似的内容不会重复写入；明显冲突会进入私有冲突列表，不会覆盖旧记忆。

### 候选记忆

当规则识别到可能长期稳定的信息时，只创建待确认候选：

- 用户偏好
- 长期目标
- 稳定习惯
- 稳定习惯和持续约束
- 重要人物关系（仅在用户明确要求保存时）
- 项目偏好和边界

候选保存在 `data/private/memory_candidates.json`，包含内容、分类、来源、原始表达、创建时间、置信度、敏感级别、状态、重复/冲突目标和生成原因。旧候选缺少这些字段时会在读取视图中补默认值，不强制改写私人文件。

不会自动生成候选的内容包括一次性计划、临时情绪、普通知识问答、模型推断信息，以及未经明确保存请求的健康、心理、家庭和身份信息。关闭 `enable_memory_candidates` 后不会生成新候选，已有候选仍可审核。

## 确认流程

支持以下聊天命令：

```text
查看待确认记忆
查看待审核记忆
确认记忆1
确认候选1
保存记忆1
忽略记忆1
忽略候选1
删除候选记忆1
清空待确认记忆
```

- 确认：先判断重复、可合并和冲突；只有新信息才直接写入 `memory.json`。
- 编辑后确认：以用户最终确认的编辑内容进入同一检查流程。
- 忽略：候选状态改为 `rejected`，不写入长期记忆。
- 删除：从候选文件移除指定条目。
- 清空：将所有 pending 候选标记为 rejected。

桌宠右键菜单中的“记忆管理”和聊天窗口中的“记忆”按钮可打开统一面板。Local Web 的长期记忆区域包含长期记忆、待审核、冲突和审计四个视图，页面按钮均调用确定性 API。

## 相关记忆检索

普通聊天先由 `MemoryRetriever` 根据当前用户输入检索，再把结果交给 `ContextBuilder`。会话摘要不会改变 health、relationship 等敏感类别的相关性判断。排序使用中文关键词、标签、文本包含、`SequenceMatcher` 相似度、类别、重要度、最近使用时间和使用次数，不依赖向量数据库。

类别相关只能作为加权，不能代替当前主题证据。“学习”“模型”“任务”等泛化词不会单独选中某条具体学习或项目记忆；当前输入还需与记忆内容、标签或具体主题形成足够匹配，避免旧话题把新问题带偏。

- 普通聊天最多注入 5 条相关记忆。
- 明确询问 Roxy 记得什么时最多读取 8 条。
- health、relationship 类别只有在问题明显相关时注入。
- 最近聊天里的旧健康或关系话题也会按当前问题过滤，避免无关学习、编程和项目回答被个人信息干扰。
- 被实际注入的记忆会更新 `last_used_at` 和 `use_count`。
- 待审核候选、已归档记忆和未解决冲突默认不参与检索。

### 当前状态与会话抑制

上下文优先级为：当前对话明确事实 > 最近确认的当前状态 > 当前计划 > 稳定身份 > 历史状态 > 未来意向。籍贯不会覆盖当前所在地点，未来愿望也不会当作当前现实。用户在本轮明确更正地点时，本轮立即按新状态回答，同时只生成待审核候选，不静默覆盖正式记忆。

健康、关系等敏感记忆按每条当前消息重新判断。上一轮使用过健康记忆，不代表下一轮闲聊仍会注入。用户说“不要再提某话题”后，当前会话会临时抑制相应类别；用户之后主动问到该主题时可按当下问题临时恢复使用。抑制不会删除或归档长期记忆。

## 冲突与整理

冲突保存在 `data/private/memory_conflicts.json`。用户可以选择“使用新记忆”“保留旧记忆”“人工合并”“两条都保留”或“暂不处理”，程序不会自动覆盖。

修改、归档、恢复、候选审核和冲突解决会写入 `data/private/memory_audit.json`。审计只保存在本地私有目录；控制台日志只打印动作和 ID，不打印完整敏感正文，Web 审计接口也只返回元数据和正文长度。私有 JSON 损坏时会在 `data/private/backups/` 保存损坏副本并使用空结构安全降级。

`整理记忆` 只统计可能重复、长期未使用、待处理冲突和过于模糊的内容，不会自动删除。长期记忆还支持搜索、分类查看、归档和恢复。

## 隐私边界

- `memory.json` 和整个 `data/private/` 都是本地私人数据，不应提交到公开仓库。
- 今日计划、行动记录和复盘不会自动转为长期记忆。
- 普通聊天不会批量提取记忆；规则无法确认时继续走普通聊天。
- 健康、心理、家庭和身份信息默认不生成候选；只有用户明确要求记住时才进入敏感候选，并且仍需确认。
- 当前版本不调用 LLM 判断候选，也不提供云端同步。

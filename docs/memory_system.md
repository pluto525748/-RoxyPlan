# RoxyPlan 智能记忆系统

## 当前范围

V1.7.3-A 用统一 `MemoryService` 连接桌面记忆面板、聊天 Agent 和 Local Web 适配器，并保留旧候选结构、冲突处理和审计能力。V2.2 普通聊天主入口采用更直接且更严格的知情写入合同：显式且内容完整的“记住……”可直接调用正式记忆工具；隐式发现的普通稳定信息只能先提出具体的正式保存建议，用户确认前不创建磁盘候选、不写正式长期记忆；隐式敏感信息不主动建议保存。旧候选结构只作内部数据兼容，不是用户能力。

## 统一业务入口

`MemoryService` 不保存第二份数据。它组合现有 `MemoryManager`、`MemoryCandidateManager`、`MemoryGovernanceService` 和同一个 `MemoryRepository`，并返回不会是 `None` 的 `MemoryOperationResult`。

`MemoryDataQueryGuard` 在普通聊天前识别正式记忆数据查询，并先执行否定、能力询问与纠正拦截。普通聊天只有一种用户可见的记忆读取来源：正式长期记忆。旧候选措辞不会别名成正式读取：聊天中提出查看、创建、确认、拒绝、删除或清空候选时，统一零工具退出并给出正式保存／读取方式。候选管理工具、真实候选 ID 和原有 `ReferenceResolver` 只为内部兼容保留，不进入模型可见目录或正常 UI。

- 正式记忆面板按钮通过服务执行编辑、归档、恢复、删除和冲突处理。
- Agent 的正式记忆工具只调用服务，不直接读写 JSON。
- Local Web 适配器使用同一服务，同时保留原 API 的兼容返回结构。
- `conversation_id` 只标识聊天会话；切换会话不会改变长期记忆、候选、冲突、Repository 或数据根目录。
- 现有 Repository 继续负责原子替换和本机轻量锁，真实 JSON 格式没有变化。

## 类型化正式读取与身份权威

2026-09-16 的收口将正式记忆读取拆为 `MemoryReadRequest → TypedMemoryReader → MemoryReadSnapshot`，仍通过现有 `list_memories` 工具与共享 `MemoryService` 执行，不增加 Provider，也不迁移私人数据。

- `query_mode` 支持 `overview / attribute / existence / provenance`。宽泛查看才使用 overview；具体问题按称呼、偏好、习惯、目标、项目或当前信息读取，必要时由 topic 限定饮食、学习、工作、地点或具体主题。
- 模型参数说明与运行时参数校验都来源于 `ToolRegistry`；读写工具均提供参数类型和合法枚举，关闭或隐藏的工具不出现在说明中。缺少必要属性或非法参数不能回退为整份用户画像。
- 每条返回事实携带真实 memory ID、内容、呈现值、日期、记录来源和数据权威。记录来源（例如用户明确保存）与存储权威（正式长期记忆或兼容 profile）分开，不能把正式保存的用户事实说成兼容资料。
- 称呼优先使用已核验的正式记忆；没有正式称呼时才回退到有效的旧 profile.nickname，拒绝“我”“你”“用户”等占位值。按真实更新时间排序，同秒更新再以稳定递增 ID 选择最新记录。桌面问候、模板、模型上下文和属性读取使用同一入口。
- `working_memories()` 统一排除 temporary_state、归档、未解决冲突和未生效/过期/非法有效期记录。临时记忆的存储结构及面板管理仍保留，但不参与普通检索、身份读取和工作上下文；没有自动删除旧数据。
- 查到什么就只回答对应事实；找不到明确说明正式记忆没有相关记录，不推断“你从未告诉过我”。询问助手本人的名字或喜好保持普通聊天。
- 类型化工具成功后，用户可见回答优先交给当前现有模型自然组织。具体属性、存在性与来源问题只提供匹配事实；宽泛了解问题提供全部有效正式事实，模型可自主选择详略；明确“全部／所有／完整／逐条”时必须覆盖全部事实。模型只能输出自然回答和实际引用的记忆 ID，本地会核验 ID、正文事实与完整性；失败重试一次后才回退到确定性模板，没有成功 ToolResult 时不能生成记忆结论。

## 长期记忆结构

`MemoryManager` 兼容旧 `memory.json`。检测到旧结构时，会先把原文件完整备份到 `data/private/backups/memory_时间戳.json`，再原子写入新结构。备份失败时不会覆盖原文件。

每条长期记忆包含 ID、内容、类别、创建/更新时间、重要度、最近使用时间、使用次数、状态、来源和标签。支持类别：偏好、目标、习惯、项目、学习、健康、重要关系、明确规则和其他。

可选时空字段包括 `scope`、`location`、`valid_from`、`valid_until`、`last_confirmed_at`、`supersedes` 和 `contradicted_by`。作用域支持：当前状态、稳定身份、历史状态、未来意向、偏好、临时状态和持续约束。旧数据缺少这些字段时只在运行时补默认值，不因普通加载强制改写私人文件。

### 明确记忆

用户明确输入下列形式，且待保存内容完整时，可以直接进入正式记忆保存流程：

- `记住：我喜欢安静的学习环境`
- `帮我记住我周末适合整理项目`

只有成功的 `save_formal_memory` ToolResult 才允许回复“已经记住”。完全重复或高度相似的内容不会重复写入；明显冲突不会静默覆盖旧记忆。若显式命令内容缺失或引用无法可靠解析，系统应澄清或诚实退出，而不是保存猜测正文。

### 隐式正式记忆保存建议

普通对话中识别到可能长期稳定的信息时，只能向用户提出一条具体保存建议，并在当前进程建立有界确认状态：

- 用户偏好
- 长期目标
- 稳定习惯
- 稳定习惯和持续约束
- 重要人物关系（仅在用户明确要求保存时）
- 项目偏好和边界

这类隐式建议在用户确认前只存在于当前进程的 `formal_memory_save` 交互状态，不写入 `data/private/memory_candidates.json`，也不写 `memory.json`。用户确认后才调用正式记忆工具；取消、超时或澄清耗尽会直接清除状态。

`data/private/memory_candidates.json` 仍用于兼容旧数据和既有内部 API，字段包括内容、分类、来源、原始表达、创建时间、置信度、敏感级别、状态、重复/冲突目标和生成原因。它不是普通聊天隐式检测的前置落盘区；旧候选缺少字段时只在内部读取视图中补默认值，不强制改写私人文件。

不会自动建议或保存的内容包括一次性计划、临时情绪、普通知识问答、模型推断信息，以及未经明确保存请求的健康、心理、家庭和身份信息。旧 `enable_memory_candidates` 字段仅作配置兼容，不再作为用户设置展示；它不改变 V2.2 普通聊天确认前零落盘规则。

## 候选内部兼容边界

候选数据结构、服务方法、旧处理器和确定性 API 暂时保留，以免大规模删除破坏旧数据兼容；这些都不是当前产品入口。桌面记忆面板、全局设置和 Local Web 页面不展示候选功能，模型工具目录也不包含候选能力。普通聊天不开放候选列表和编号引用；用户说“查看待确认记忆”“确认候选1”或“清空待确认记忆”时，不读取正式记忆、不改候选数据，只说明功能已停用并提供正式记忆表达。

- 兼容层可以读取并解析旧候选文件，但正常聊天和页面不触发这些操作。
- 旧 API/handler 的存在用于保持格式和测试兼容，不得被能力介绍、提示词或模型 schema 宣称为可用功能。
- 后续若要物理删除候选架构，必须另行评估旧数据、Repository、服务和测试迁移，不在 V2.2 封版中大拆。

桌宠右键菜单中的“记忆管理”和聊天窗口中的“记忆”按钮可打开正式记忆面板。Local Web 的长期记忆区域展示长期记忆、冲突和审计，不展示候选页。

## 相关记忆检索

普通聊天先由 `MemoryRetriever` 根据当前用户输入检索，再把结果交给 `ContextBuilder`。会话摘要不会改变 health、relationship 等敏感类别的相关性判断。排序使用中文关键词、标签、文本包含、`SequenceMatcher` 相似度、类别、重要度、最近使用时间和使用次数，不依赖向量数据库。

类别相关只能作为加权，不能代替当前主题证据。“学习”“模型”“任务”等泛化词不会单独选中某条具体学习或项目记忆；当前输入还需与记忆内容、标签或具体主题形成足够匹配，避免旧话题把新问题带偏。

- 普通聊天最多注入 5 条相关记忆。
- 明确属性问题只返回已核验的匹配事实；宽泛查看正式记忆走工具读取，不把旧检索器的 8 条提示预算当作正式记忆总量。
- health、relationship 类别只有在问题明显相关时注入。
- 最近聊天里的旧健康或关系话题也会按当前问题过滤，避免无关学习、编程和项目回答被个人信息干扰。
- 构建提示和注入上下文不更新 `last_used_at` / `use_count`。只有最终显示回答确实引用对应事实时才更新；每轮证据随 `ConversationTurn` 传递，类型化读取按成功 ToolResult 的调用 ID 去重。模型自然回答只采用已通过事实校验的 `used_memory_ids`，本地兜底继续使用保守正文核心匹配；无法确认的改写不计为使用。
- 旧直接调用 `MemoryRetriever.retrieve()` 的兼容 API 仍可显式选择即时计数；共享产品聊天路径统一传入 `update_usage=False`，在最终回答后核验计数。
- 待审核候选、已归档记忆、temporary_state、无效有效期与未解决冲突默认不参与工作检索。

2026-09-18 增加会话内少量真实记忆续接：仅成功的正式读取／保存工具结果进入进程缓存，最多五条，并使用已有短时引用有效期。下一轮先按 ID、正文、创建时间和当前有效状态重新核验；归档、删除、冲突、过期、临时记录及无关敏感事实不能借旧缓存重新进入工作上下文。当前检索未召回不等于“从未保存”；模型只按相关已核验事实自然回答，不整段复读。缓存本身不落盘、不自动创建记忆，最终回答实际引用后才更新使用状态。该改动本轮仅静态检查，尚待用户桌面验收。

### 当前状态与会话抑制

上下文优先级为：当前对话明确事实 > 最近确认的当前状态 > 当前计划 > 稳定身份 > 历史状态 > 未来意向。籍贯不会覆盖当前所在地点，未来愿望也不会当作当前现实。用户在本轮明确更正地点时，本轮立即按新状态回答；如该信息适合长期保存，只能提出具体建议并等待确认，确认前不生成磁盘候选，也不静默覆盖正式记忆。

健康、关系等敏感记忆按每条当前消息重新判断。上一轮使用过健康记忆，不代表下一轮闲聊仍会注入。用户说“不要再提某话题”后，当前会话会临时抑制相应类别；用户之后主动问到该主题时可按当下问题临时恢复使用。抑制不会删除或归档长期记忆。

## 冲突与整理

### 精确聊天删除（2026-09-18，待用户桌面验收）

聊天删除仅保留“忘记：完整记忆正文”（英文冒号也可）。本地把正文当作不透明数据，只去除首尾空白，按完整内容等值匹配正式记录，不依赖模型 ID、关键词或模糊检索。唯一匹配时才经现有工具链展示真实编号与完整正文，等待一次“确认／取消”；零匹配或同文多条不删除，指向记忆管理面板。

初次确认前，在现有本机记忆事务中校验匹配时的编号、正文和创建时间；确认核验至实际删除持有同一可重入事务锁。目标被修改、删除或替换即使编号相同也停止；正常读取造成的使用次数变化不影响确认。删除不清除历史聊天、旧 profile、审计或备份，不新增公开参数或模型删除能力。

### 既有冲突与维护

冲突保存在 `data/private/memory_conflicts.json`。用户可以选择“使用新记忆”“保留旧记忆”“人工合并”“两条都保留”或“暂不处理”，程序不会自动覆盖。

修改、归档、恢复、候选审核和冲突解决会写入 `data/private/memory_audit.json`。审计只保存在本地私有目录；控制台日志只打印动作和 ID，不打印完整敏感正文，Web 审计接口也只返回元数据和正文长度。私有 JSON 损坏时会在 `data/private/backups/` 保存损坏副本并使用空结构安全降级。

`整理记忆` 只统计可能重复、长期未使用、待处理冲突和过于模糊的内容，不会自动删除。长期记忆还支持搜索、分类查看、归档和恢复。

编辑正式记忆正文且未显式提供 tags 时，标签随最终正文重新提取，避免旧标签把后续检索引向已经改掉的事实；显式提供的标签仍按原管理 API 契约处理。

## 隐私边界

- `memory.json` 和整个 `data/private/` 都是本地私人数据，不应提交到公开仓库。
- 今日计划、行动记录和复盘不会自动转为长期记忆。
- 普通聊天不会批量提取记忆；规则无法确认时继续走普通聊天。
- 健康、心理、家庭和身份信息默认不建议保存、不生成 pending 或磁盘候选；只有用户明确要求记住且内容完整时，才允许进入正式记忆保存流程。
- 兼容候选治理本身不额外调用 LLM；普通聊天的语义层可以提出保存建议，但本地边界仍负责敏感拦截、确认前零落盘和 ToolResult 真实性校验。当前版本不提供云端同步。

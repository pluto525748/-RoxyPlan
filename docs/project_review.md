# RoxyPlan 项目审查报告

## 1. 审查结论

从资深 AI 产品经理角度看，RoxyPlan 的方向有价值，但当前规划存在明显过度设计。

项目最重要的判断是：

RoxyPlan 的核心不是聊天，也不是单纯情感陪伴，而是帮助用户持续成长。

所有功能都必须优先服务：

- 学习
- 健康
- 项目
- 赚钱
- 长期成长

当前项目的主要问题不是想得不够，而是想得太多。  
如果一开始同时推进桌宠、人格、聊天、长期记忆、成长日志、知识库、语音、手机版、跨端同步和商业化，极大概率会导致 MVP 迟迟无法落地。

建议：

- MVP 只保留“成长记录闭环”。
- 桌宠和聊天只作为入口。
- 记忆只保留最小可控版本。
- 知识库、语音、手机版全部延后。
- 收入、健康和心情记录早期只做轻量设计，不做复杂系统。

## 2. 过度设计部分

### 2.1 人格系统过重

当前人格系统设计很完整，但早期不需要这么多细则。

过度点：

- 情绪规则过细。
- 陪伴规则较多。
- 健康监督规则过完整。
- 禁止行为覆盖面很大。
- 容易把产品重心拉回“情感陪伴”。

产品判断：

人格系统需要有，但 MVP 只需要保留基础语气和安全边界。

MVP 保留：

- 温柔、清楚、克制。
- 不羞辱用户。
- 不制造依赖。
- 不做医疗诊断。
- 不自动保存敏感记忆。

延后：

- 复杂情绪识别。
- 多场景陪伴语气。
- 深度心理安抚。
- 复杂健康监督。

原因：

RoxyPlan 的主线是成长，不是情绪陪聊。人格系统应该支撑成长行动，而不是成为产品主体。

### 2.2 长期记忆结构过复杂

当前长期记忆设计区分用户档案、长期目标、学习记录、项目记录、健康记录、成长记录、兴趣爱好。这适合作为长期架构，但不适合 MVP。

过度点：

- 记忆类型太多。
- 字段太细。
- 审计日志、敏感规则、成长状态一起上会增加实现和管理成本。
- 容易让用户不知道哪些内容被记住。

MVP 保留：

- 用户称呼。
- 沟通偏好。
- 1 到 3 个长期目标。
- 重要项目摘要。
- 用户明确要求记住的内容。
- 查看和删除记忆。

延后：

- 健康记忆。
- 兴趣爱好体系。
- 成长阶段记忆。
- 完整审计日志。
- 复杂记忆分类。

原因：

记忆的价值在于准确、可控、有用，不在于分类多。

### 2.3 知识投喂系统过早

知识投喂系统设计完整，但它是 V3 能力，不应进入 MVP 或早期 V1。

过度点：

- 同时支持 PDF、Word、PPT、TXT、Markdown。
- 设计了解析、分块、摘要、标签、实体关系、检索、引用。
- 技术复杂度远高于早期产品验证需要。

MVP 删除：

- 文件上传。
- 文档解析。
- 知识库索引。
- 对话引用。

V1 也建议不做完整知识投喂。

后续优先级：

1. TXT 和 Markdown。
2. PDF。
3. Word。
4. PPT。

原因：

知识投喂必须建立在稳定记录、计划和复盘体系之上。否则用户即使上传资料，也不会形成持续成长闭环。

### 2.4 成长日志系统字段过多

成长日志是 RoxyPlan 的核心，但当前设计过于完整。

过度点：

- 学习、项目、健身、收入、心情五类同时完整设计。
- 每类字段较多。
- 周报和月报系统过早完整化。
- 收入和心情都涉及隐私，早期实现风险较高。

MVP 保留：

- 今日计划。
- 学习记录。
- 项目记录。
- 每日一句总结。
- 简单周总结。

延后：

- 健身完整记录。
- 收入记录。
- 心情趋势。
- 月报系统。
- 多维度图表。

原因：

成长日志必须先让用户愿意每天记。字段越多，用户越容易放弃。

### 2.5 桌宠交互系统过重

桌宠是差异化入口，但早期不需要复杂状态机。

过度点：

- 状态过多。
- 右键菜单过完整。
- 通知规则较复杂。
- 投喂状态、成长庆祝状态等早期没有必要。

MVP 保留：

- 待机。
- 聊天。
- 提醒。
- 隐藏。
- 退出。

延后：

- 投喂状态。
- 成长庆祝。
- 复杂悬停行为。
- 多级右键菜单。
- 丰富动画。

原因：

桌宠早期只要证明“常驻入口 + 低打扰提醒”成立即可。

### 2.6 语音系统过早

语音能增强陪伴感，但不是 MVP 必需。

过度点：

- STT、TTS、本地部署、API 方案同时设计。
- 固定声线、连续对话、隐私模式都需要较高成本。
- 语音会放大模型回复质量和延迟问题。

MVP 删除：

- STT。
- TTS。
- 连续对话。
- 固定声线。

延后到 V2 或更晚。

原因：

文字记录都没有被验证前，语音只是更贵、更复杂的输入方式。

### 2.7 手机版过早

手机浏览器访问是有价值的，但不应进入早期版本。

过度点：

- 页面结构完整。
- 导航结构完整。
- 数据同步方案复杂。
- 涉及账号、权限、冲突、离线和隐私锁。

MVP 删除：

- 手机端。
- 跨端同步。
- 离线草稿。
- 手机端知识库查询。

延后到桌面端成长闭环验证之后。

原因：

跨端会让数据架构和隐私复杂度显著上升。桌面端价值未验证前，不应扩展端。

## 3. 风险点

### 3.1 产品主线偏移风险

最大风险是从“成长系统”滑向“AI 聊天陪伴”。

表现：

- 聊天窗口成为唯一主界面。
- 用户主要用来闲聊。
- 记录、计划、项目推进不够突出。
- Roxy 的人格设计抢过成长功能。

应对：

- 首页和桌宠提醒都围绕今日计划。
- 聊天中优先沉淀记录和下一步行动。
- 周总结围绕学习和项目，而不是情绪聊天摘要。

### 3.2 范围失控风险

当前规划包含太多系统：

- 桌宠。
- 聊天。
- 记忆。
- 成长日志。
- 知识库。
- 语音。
- 手机端。
- 商业化。

风险：

- 每个功能都做不深。
- MVP 无法按时落地。
- 用户不知道产品到底解决什么问题。

应对：

- 版本范围必须强制冻结。
- MVP 只验证一个闭环：计划、记录、复盘。

### 3.3 隐私风险

RoxyPlan 涉及大量敏感数据：

- 健康。
- 心情。
- 收入。
- 长期目标。
- 学习和项目状态。
- 聊天内容。

风险：

- 用户不敢记录真实信息。
- 同步和手机端展示可能泄露隐私。
- 自动记忆容易引发信任问题。

应对：

- 本地优先。
- 敏感信息默认不保存。
- 保存前确认。
- 用户可查看、编辑、删除。
- 收入和心情记录延后。

### 3.4 AI 回复不稳定风险

Roxy 需要长期监督用户成长，但 AI 回复可能：

- 过度鼓励。
- 过度说教。
- 生成不现实计划。
- 编造记忆。
- 把用户情绪判断当事实。

应对：

- MVP 降低 AI 自主度。
- 使用固定记录模板。
- 重要记忆必须用户确认。
- 提醒和建议短句化、可执行化。

### 3.5 留存风险

用户可能前几天觉得新鲜，随后停止记录。

原因：

- 记录成本高。
- 周报没有价值。
- 提醒像打扰。
- 看不到成长反馈。

应对：

- 每日记录必须极轻量。
- 支持一句话记录。
- 周总结必须让用户看到具体变化。
- 只推 1 到 3 个今日重点。

### 3.6 商业化风险

如果产品价值不清，用户不会付费。

风险：

- 用户觉得它只是 ChatGPT 换皮。
- 用户觉得成长记录不如 Notion。
- 用户觉得知识库不如 NotebookLM。
- 用户觉得语音不如成熟语音助手。

应对：

- 付费点必须绑定长期成长成果。
- 不为聊天收费，优先为周报、月报、知识库、语音复盘和毕业成长档案收费。

## 4. 技术难点

### 4.1 桌宠稳定性

难点：

- 常驻桌面。
- 不遮挡。
- 可拖动。
- 低资源占用。
- 与聊天窗口交互。
- 系统通知和退出控制。

产品建议：

- MVP 不追求复杂动画。
- 只实现基础头像、点击、移动、隐藏、退出。

### 4.2 长期记忆可靠性

难点：

- 判断什么值得记。
- 避免错误记忆。
- 避免敏感信息误存。
- 记忆更新和删除。
- 对话中正确使用记忆。

产品建议：

- MVP 不做自动记忆。
- 只做用户确认后保存。
- 记忆数量少而可控。

### 4.3 成长记录结构化

难点：

- 用户自然语言输入如何转成结构化记录。
- 如何避免字段太多。
- 如何生成有价值周总结。
- 如何把学习、项目和计划关联起来。

产品建议：

- MVP 使用简单模板。
- 先支持学习和项目两类。
- 周总结先做轻量文本摘要。

### 4.4 数据存储边界

难点：

- SQLite、memory.json、growth_log、chat_history、knowledge_base 的边界。
- 数据迁移。
- 数据导出。
- 隐私删除。

产品建议：

- MVP 只需要 SQLite + memory.json。
- knowledge_base、chat_history 导出、growth_log 导出延后。

### 4.5 知识库检索

难点：

- 多格式解析。
- 文本分块。
- 语义检索。
- 来源引用。
- 幻觉控制。
- 与长期记忆区分。

产品建议：

- V3 再做。
- 先从 TXT 和 Markdown 开始。
- 必须带来源引用。

### 4.6 语音延迟和声线稳定

难点：

- STT 准确率。
- TTS 延迟。
- 固定声线一致性。
- 连续对话打断。
- 隐私告知。

产品建议：

- V2 之后再做。
- 先做手动触发语音输入。
- 不做永久监听。

### 4.7 手机端同步

难点：

- 账号系统。
- 跨端同步。
- 冲突处理。
- 离线草稿。
- 敏感数据展示。

产品建议：

- 桌面端验证成功后再做。
- 手机端先只读今日计划和成长记录摘要。

## 5. 不必要功能

### 5.1 MVP 不必要

以下功能不应进入 MVP：

- 语音输入。
- AI 语音回复。
- 固定声线。
- 连续对话。
- PDF、Word、PPT 投喂。
- 知识库检索。
- 手机浏览器访问。
- 跨端同步。
- 收入记录。
- 完整健康记录。
- 心情趋势。
- 月报系统。
- 复杂成长等级。
- 多皮肤。
- 复杂动画。
- 高级右键菜单。
- 自动长期记忆。

### 5.2 V1 也不必要

以下功能即使到 V1 也不建议做：

- 多格式知识投喂。
- 完整语音系统。
- 手机端。
- 收入报表。
- 高级知识图谱。
- 本地 STT/TTS 部署。
- 复杂商业化套餐。

### 5.3 可以长期不做

以下功能即使未来也要谨慎：

- 恋爱化陪伴。
- 占有式人格表达。
- 永久在线监听。
- 自动保存敏感记忆。
- 基于健康数据做诊断。
- 用收入、学习时长或健身次数评价用户价值。

## 6. MVP 应该保留什么

### 6.1 MVP 核心闭环

MVP 必须围绕一个闭环：

```text
今日计划 -> 行动记录 -> Roxy 反馈 -> 周总结 -> 下周计划
```

这是 RoxyPlan 的真正核心。

聊天只是输入方式。  
桌宠只是入口。  
记忆只是让成长计划更连续。

### 6.2 MVP 必须保留功能

必须保留：

- 桌宠头像。
- 点击打开主窗口。
- 文本聊天。
- 今日计划。
- 学习记录。
- 项目记录。
- 基础长期目标。
- 基础长期记忆。
- 简单周总结。
- 基础人格和安全边界。
- 查看和删除记忆。
- 隐藏或退出桌宠。

### 6.3 MVP 数据范围

MVP 只需要保存：

- 用户称呼。
- 用户沟通偏好。
- 1 到 3 个长期目标。
- 今日计划。
- 学习记录。
- 项目记录。
- 最近聊天记录。
- 周总结。

不保存：

- 收入流水。
- 健康敏感信息。
- 心情私密记录。
- 文档知识库。
- 复杂成长等级。

### 6.4 MVP 页面范围

MVP 页面建议：

- 桌宠入口。
- 主窗口。
- 今日计划页。
- 记录页。
- 记忆页。
- 简单设置页。

不需要：

- 知识库页。
- 手机端页面。
- 语音设置页。
- 收入页。
- 健身趋势页。
- 心情趋势页。
- 完整月报页。

### 6.5 MVP 验收标准

MVP 成功标准：

- 用户连续 7 天至少 4 天打开 Roxy。
- 用户每周至少记录 3 次学习或项目进度。
- 用户愿意让 Roxy 保存至少 1 个长期目标。
- 用户愿意查看周总结。
- 用户认为 Roxy 对推进学习或项目有帮助。

MVP 失败信号：

- 用户只闲聊，不记录。
- 用户不愿意保存目标。
- 用户觉得提醒打扰。
- 用户看完周总结没有行动变化。
- 用户第二天不再打开桌宠。

## 7. 推荐版本收敛

### 7.1 MVP

目标：

- 验证成长闭环。

范围：

- 桌宠入口。
- 文本聊天。
- 今日计划。
- 学习记录。
- 项目记录。
- 基础记忆。
- 简单周总结。

### 7.2 V1

目标：

- 稳定日常成长管理。

范围：

- 更好的桌宠状态。
- 学习提醒。
- 项目提醒。
- 轻量休息提醒。
- 成长记录列表。
- 周总结增强。
- 基础数据导出。

### 7.3 V2

目标：

- 提高记录和复盘效率。

范围：

- 语音输入。
- AI 短语音回复。
- 健身记录。
- 心情记录。
- 月报基础版。

### 7.4 V3

目标：

- 让 Roxy 成为个人知识伙伴。

范围：

- TXT 和 Markdown 投喂。
- PDF 投喂。
- 知识库查询。
- 来源引用。
- 项目与知识绑定。

### 7.5 V4 以后

范围：

- Word 和 PPT。
- 手机浏览器访问。
- 跨端同步。
- 收入记录和赚钱复盘。
- 本地隐私模式。
- 毕业成长档案。

## 8. 最重要的产品建议

### 8.1 不要让聊天成为主产品

聊天应该服务记录、计划和复盘。

每次聊天后，Roxy 应尽量沉淀出：

- 一个记录。
- 一个计划。
- 一个目标更新。
- 一个下一步行动。

### 8.2 不要一开始做知识库

知识库很诱人，但不是第一步。

先验证用户是否愿意记录自己的成长。  
如果用户连成长记录都不愿意写，知识库再强也留不住人。

### 8.3 不要一开始做语音

语音会让体验更自然，但也会让成本和风险变高。

文字 MVP 成立后，语音才有意义。

### 8.4 不要一开始做手机版

手机版是扩展，不是验证核心价值的入口。

先证明桌面端 Roxy 能让用户持续记录和复盘。

### 8.5 把赚钱放进长期路线，但不要放进 MVP

赚钱是 RoxyPlan 的重要差异化，但收入记录敏感，不适合 MVP。

MVP 可以保留“项目目标”和“变现方向”描述，不保存具体金额流水。

## 9. 最终判断

RoxyPlan 值得继续推进，但必须大幅收敛。

当前最推荐的 MVP 定义是：

```text
一个桌面 AI 成长伙伴，帮助用户每天制定计划、记录学习和项目进度，并生成简单周总结。
```

这比“AI 桌宠聊天助手”更有商业价值，也更符合 RoxyPlan 的长期目标。

先让用户持续成长，再让 Roxy 变得更聪明、更会说话、更懂资料。

顺序不能反。

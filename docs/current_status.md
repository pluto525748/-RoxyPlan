## 当前生产原则

- 非精确自然语言每轮只形成一个 canonical `SemanticDecision`。
- 精确命令门只保留完整匹配的桌宠动作、固定 UI 管理命令和当前会话确认/取消。
- 模型语义层可以提出 `chat/read/write/clarify`、意图、实体和候选工具；程序再归一化为 `chat_only/tool_then_reply/clarify` 的 canonical `SemanticDecision`，且两层都没有执行权限。
- `BusinessResolver` 绑定真实对象并校验必要字段；`CapabilityRegistry` 唯一决定模型可见性与执行策略；`ToolRegistry` 提供 schema/handler；`ToolExecutor` 执行最终允许的工具；`ToolResult` 是回复事实依据。
- 成功只读结果不会被写声明守卫误拦截；写操作没有匹配的成功 ToolResult 时不能声称完成。
- 否定、建议、讨论和能力询问不能因出现业务名词而触发读写工具；当前句明确日期优先于旧上下文或模型残留日期。
- 会话内列表引用使用带稳定 ID 与展示顺序的 `ReadSnapshot`，实际写入前必须重新读取当前对象；批量完成只做一次整体确认，澄清最多两轮。
- 桌面端和 Local Web 共用 `ConversationService`、人格、上下文和业务服务，不维护第二套业务路由。

## 已落地能力

### V1.9 安全交互基线

- 命令文本与业务载荷隔离，载荷内部的动作词不会二次触发工具。
- 普通陈述、否定、赞美、咨询和知识问答零副作用。
- 模糊引用不能成为计划、行动或记忆正文；包含写操作的模糊批次零执行。
- pending clarification、confirmation、上一轮事实来源和“刚才”按 `conversation_id` 隔离。
- 明确低风险记忆通过 `save_formal_memory` 一次正式保存；普通聊天不自动保存。
- 正式记忆保存后可在当前会话短 TTL 内撤销，底层使用 archive。
- 候选记忆底层只作内部兼容保留，退出普通聊天、模型能力目录以及桌面和 Local Web 的正常用户入口。
- 桌宠动作统一经 `DesktopClientActionDispatcher` 派发，不在 ConversationService 之后由旧 UI handler 二次扫描自然语言。

### V2.0 人格与连续性

- `data/personas/roxy/` 包含 manifest、identity、behavior、speaking style、truth boundaries、relationships、lore、examples、evaluation cases 和 assets metadata。
- `PersonaRegistry` 与 `PersonaPack` 负责扫描、加载、校验和回退，不管理聊天、记忆或工具生命周期。
- 当前人格通过设置面板的 `active_persona_id` 选择；聊天消息不能切换角色。
- `ContextBuilder` 统一注入安全边界、人格核心、正式目标、今日状态、当前会话、相关旧摘要、相关记忆、人格材料和知识，并记录 section 字符预算与裁剪诊断。
- `ChatHistoryManager` 支持 finalize/update session summary，并按 query、persona、新近度和字符预算检索相关旧摘要。
- 新窗口可知道过去大概讨论过什么，但不继承确认、澄清、序号、“刚才”和撤销状态，也不根据摘要编造精确原句或工具事实。

### V2.1 统一语义与回复真实性

- 所有自然语言语义输出归一化为一份 `SemanticDecision`；主回复完成后不再运行 JSON action fallback 或旧 natural-intent handler。
- `chat + tools=none` 保持普通聊天，不会仅因没有工具进入 clarification。
- “你确定吗”可以在同一会话复核最近一次成功只读来源，不会进入通用执行兜底。
- 正式记忆查询经过 canonical `list_memories`，再进行去重、无效片段过滤、事实归纳、视角转换和人格化呈现。
- 正式记忆正文中的“跳舞”等词只作为事实材料，不会触发客户端动作。
- 保存上一条用户消息时，由 `ReferenceResolver` 只在当前 conversation 中解析结构化引用。引用 assistant 回复时，source 与最终 memory content 分离：必须再经过受限结构化提取并验证正文来自 source，提取失败不得回退为整段保存。成功 ToolResult 与 memory_id 仍是“已经保存”声明的必要条件。
- 普通聊天最终显示为纯文本；成对 Markdown `**` 只在最终展示边界去除强调标记，不粗暴删除合法 `*`。
- 持久化开发诊断记录 SemanticDecision、Validation、工具调用、ToolResult、MemoryAudit 和 FinalResponse 等脱敏阶段。

### V2.2 封版收口契约

- `ReadSnapshot` 只保存成功只读结果中的结构化事实：会话、工具、查询参数、稳定 ID、展示顺序及有限计划字段；列表后来变化时，序号仍指向当时展示的稳定 ID，不能重新按实时下标猜目标。
- 序号完成和“刚才展示的都完成了”会在执行前复核实时计划；缺失、已非待完成或确认前集合失效时不改到别的计划，并输出有边界的失败说明。
- 否定建议保持 `chat/tools=0`；当前句明确日期覆盖旧轮日期；批量完成展示目标后只需一次确认，确认前无数据变化；澄清最多两轮，超限取消 pending。
- 未显式要求“记住”时，普通稳定信息先询问是否保存且确认前零落盘；敏感信息不主动建议保存。显式且内容完整的保存命令仍走既有 `save_formal_memory` 与 ToolResult 契约。
- 复杂修改、合并、删除以及候选/冲突维护等能力可保留本地确定性入口，但默认对模型隐藏；模型越权提议时统一返回“本次没有完成”的诚实降级，不伪造 ToolResult。
- 历史会话自然查询只做本地轻量模糊检索，返回真实旧会话摘要、片段、日期或来源并排除当前会话；没有匹配时明确说没有找到，不使用向量数据库，也不根据当前对话补写旧事实。
- 启动时的昨日复盘补齐只处理一个日期且幂等；设置默认开启且独立于晚间提醒，已有日志不自动覆盖、空白日不落盘、后台不调用模型。自然月成长日志只统计目标 `YYYY-MM`，模型总结只能消费成功工具返回的已核验 JSON。

# RoxyPlan 语音系统设计

## 1. 设计目标

RoxyPlan 的语音系统不是为了做一个普通语音聊天机器人，而是为了让用户在学习、健康、项目、赚钱和长期成长场景中更低成本地与 Roxy 互动。

语音系统应服务于：

- 学习监督：用户可以口头汇报学习进度、复述知识点、请求讲解。
- 健康提醒：Roxy 可以用温和语音提醒休息、喝水、活动身体。
- 项目推进：用户可以快速口述项目进度、阻塞和下一步。
- 收入记录：用户可以口头记录收入、兼职、项目变现进展。
- 长期成长：语音让复盘、周报和月报更自然。

核心功能：

1. 用户语音输入。
2. AI 语音回复。
3. 固定角色声线。
4. 连续对话模式。

设计原则：

- 语音是成长效率工具，不是纯闲聊功能。
- 语音回复要短、清楚、可执行。
- 固定声线要稳定，避免频繁变化破坏角色感。
- 连续对话必须可暂停、可静音、可退出。
- 用户隐私优先，语音内容应可控、可删除。

## 2. 核心功能设计

### 2.1 用户语音输入

用户语音输入用于把口头内容转成文字，再交给 Roxy 的对话、记录和成长系统处理。

适用场景：

- “我今天学了两小时 Python。”
- “帮我记录今天跑步 30 分钟。”
- “我这个项目卡在登录模块了。”
- “今天兼职收入 200 元。”
- “我现在有点累，提醒我休息一下。”

基础要求：

- 支持按住说话。
- 支持点击开始和点击结束。
- 支持识别结果确认。
- 支持用户修改识别文本。
- 支持取消本次输入。

不建议 MVP 一开始就做：

- 永久监听。
- 自动唤醒词。
- 多人声纹识别。
- 复杂环境降噪。

原因：

- 永久监听会带来隐私焦虑。
- 唤醒词和降噪复杂度高。
- 早期产品更需要稳定可控的语音记录能力。

### 2.2 AI 语音回复

AI 语音回复用于让 Roxy 用固定声线回应用户。

适用场景：

- 学习任务拆解。
- 健康休息提醒。
- 项目复盘摘要。
- 周报月报朗读。
- 短句陪伴和状态反馈。

基础要求：

- 可以开启或关闭语音回复。
- 支持停止播放。
- 支持调节音量。
- 支持文字和语音同时展示。
- 长回复优先显示文字，语音只播报摘要。

语音回复规则：

- 优先短句。
- 避免长篇朗读。
- 学习和项目场景要给下一步行动。
- 健康场景要温和，不做医疗判断。
- 收入场景要注意隐私，不在公共环境大声播报敏感金额，除非用户允许。

### 2.3 固定角色声线

固定角色声线是 Roxy 角色稳定性的关键。

目标：

- 让用户听到声音就知道是 Roxy。
- 声线长期稳定，不频繁切换。
- 声音风格符合“温柔、聪明、克制、可靠”的角色设定。

声线方向：

- 年轻、清澈、温和。
- 语速中等偏慢。
- 情绪表达轻，不夸张。
- 适合长时间听，不刺耳。
- 学习提醒时清楚，休息提醒时柔和。

可配置项：

- 音量。
- 语速。
- 是否自动播放。
- 是否只在提醒时播放。
- 是否在夜间自动静音。

不建议早期开放：

- 大量声线切换。
- 用户自定义克隆声音。
- 情绪化夸张声线。

原因：

- Roxy 需要固定人格。
- 过多声线会削弱角色稳定性。
- 声音克隆涉及更高隐私和授权风险。

### 2.4 连续对话模式

连续对话模式用于让用户在一段时间内自然地和 Roxy 语音交流。

适用场景：

- 学习复述。
- 项目复盘。
- 睡前总结。
- 周报访谈。
- 运动后记录。

基础流程：

1. 用户开启连续对话模式。
2. Roxy 提示当前模式和退出方式。
3. 用户说话。
4. STT 转文字。
5. Roxy 回复。
6. TTS 播放简短回复。
7. 系统等待下一轮输入。
8. 用户手动退出或超时退出。

控制规则：

- 必须有明显的开启状态。
- 必须有明显的退出方式。
- 支持静音。
- 支持暂停。
- 支持只转文字不朗读。
- 空闲一段时间后自动退出。

不建议早期做：

- 自动无限循环监听。
- 用户未确认时自动记录敏感内容。
- 在连续对话中自动写入长期记忆。

## 3. STT 方案分析

STT 是 Speech-to-Text，用于把用户语音转成文本。

### 3.1 STT 需求

RoxyPlan 的 STT 需要满足：

- 中文识别准确。
- 支持短句和中等长度口述。
- 延迟可接受。
- 支持本地或 API 两种路线。
- 识别结果可编辑。
- 适合成长记录场景。

重点不是会议级转写，而是日常记录和对话。

### 3.2 本地 STT 方案

本地方案优点：

- 隐私更强。
- 不依赖网络。
- 长期成本低。
- 更适合健康、收入和私密心情记录。

本地方案缺点：

- 初始集成复杂。
- 对设备性能有要求。
- 模型体积可能较大。
- 识别准确率取决于模型和硬件。

适合场景：

- 离线语音记录。
- 私密成长日志。
- 本地优先用户。
- 后续成熟版本。

候选方向：

- Whisper 类本地模型。
- 轻量中文语音识别模型。
- 系统自带语音识别能力。

产品建议：

- V1 不强制本地 STT。
- V2 支持 API STT 优先。
- V3 提供本地 STT 作为隐私增强选项。

### 3.3 API STT 方案

API 方案优点：

- 集成较快。
- 识别准确率通常更稳定。
- 设备压力小。
- 适合快速验证语音体验。

API 方案缺点：

- 依赖网络。
- 有调用成本。
- 语音数据会发送到服务端。
- 需要明确隐私提示。

适合场景：

- 早期快速验证。
- 在线语音聊天。
- 学习复述和项目复盘。
- 用户允许云端识别的场景。

产品建议：

- 默认提示用户语音将用于识别。
- 提供“只本次使用，不写入记忆”的说明。
- 收入、健康、心情等敏感记录保存前必须确认。

### 3.4 STT 推荐策略

推荐采用“双路线”：

- 早期使用 API STT 快速验证。
- 后期增加本地 STT，作为隐私优先模式。

STT 结果不应直接进入长期记忆。  
它应先变成可编辑文本，再由用户确认是否记录。

## 4. TTS 方案分析

TTS 是 Text-to-Speech，用于把 Roxy 的回复转成语音。

### 4.1 TTS 需求

RoxyPlan 的 TTS 需要满足：

- 中文自然度较好。
- 声线稳定。
- 适合长期听。
- 支持语速和音量调节。
- 支持短句快速播放。
- 支持固定角色声线。

### 4.2 本地 TTS 方案

本地方案优点：

- 隐私更强。
- 不依赖网络。
- 长期成本低。
- 可用于离线提醒。

本地方案缺点：

- 声音自然度可能不如 API。
- 声线调试成本较高。
- 模型体积和性能要求较高。
- 固定高质量角色声线较难。

适合场景：

- 休息提醒。
- 学习提醒。
- 简短状态反馈。
- 隐私优先用户。

### 4.3 API TTS 方案

API 方案优点：

- 声音自然度高。
- 固定声线更容易稳定。
- 可快速验证角色听感。
- 支持更细腻的语气。

API 方案缺点：

- 依赖网络。
- 有调用成本。
- 文本需要发送到服务端。
- 声线长期可用性依赖服务商。

适合场景：

- AI 语音回复。
- 周报月报朗读。
- 角色声线验证。
- 高质量陪伴体验。

### 4.4 TTS 推荐策略

推荐早期使用 API TTS 验证声线体验。

同时应预留本地 TTS 路线：

- API TTS 用于高质量角色回复。
- 本地 TTS 用于基础提醒和离线模式。

固定声线应优先稳定，不追求多样。

## 5. 本地部署方案

### 5.1 本地部署目标

本地部署用于保护隐私、降低长期成本，并提升离线可用性。

适合本地部署的能力：

- 基础 STT。
- 基础 TTS。
- 语音设置。
- 语音缓存。
- 成长记录存储。
- 本地记忆读取。

### 5.2 本地部署优点

- 用户更放心。
- 适合健康、收入、心情记录。
- 无网络时仍可使用基础语音提醒。
- 可减少长期 API 成本。

### 5.3 本地部署缺点

- 模型下载和安装复杂。
- 对电脑性能要求更高。
- 声音质量可能不稳定。
- 维护成本更高。

### 5.4 本地部署设计建议

本地部署不应作为 MVP 的硬要求。

更合理的路线：

- 先提供云端 API 语音。
- 后续加入“隐私模式”。
- 隐私模式下优先使用本地 STT/TTS。
- 用户可选择是否安装本地语音模型。

## 6. API 方案

### 6.1 API 方案目标

API 方案用于快速获得高质量 STT 和 TTS，让产品尽早验证语音交互价值。

适合 API 的能力：

- 高质量中文 STT。
- 高自然度 TTS。
- 固定角色声线。
- 连续对话中的低延迟语音交互。

### 6.2 API 方案优点

- 研发速度快。
- 体验稳定。
- 初期无需处理复杂模型部署。
- 更容易打磨角色声音。

### 6.3 API 方案缺点

- 需要网络。
- 有使用成本。
- 涉及隐私告知。
- 服务稳定性依赖供应商。

### 6.4 API 使用边界

必须明确：

- 用户知道语音会被发送用于识别或合成。
- 敏感内容保存前必须确认。
- 用户可以关闭语音功能。
- 用户可以切换到文字模式。
- 用户可以删除语音转写后的记录。

## 7. V1-V3 演进路线

## 7.1 V1：基础语音记录和固定声线验证

### 目标

验证语音是否能降低成长记录成本，并建立 Roxy 的固定声线。

### 功能范围

- 用户手动触发语音输入。
- STT 转文字。
- 用户确认识别文本。
- AI 短语音回复。
- 固定角色声线。
- 语音开关。
- 停止播放。
- 文字和语音同步展示。

### 适用场景

- 学习记录。
- 项目进度口述。
- 健身记录。
- 心情简短记录。
- 休息提醒。

### 不做内容

- 不做永久监听。
- 不做唤醒词。
- 不做自动保存敏感记录。
- 不做复杂连续对话。
- 不做多声线切换。

### 推荐方案

- STT：API 优先。
- TTS：API 优先。
- 本地部署：暂不作为必需项。

### 原因

V1 的关键是验证体验。  
如果用户愿意用语音记录学习、项目、健康和心情，说明语音系统有价值。

## 7.2 V2：连续对话和成长复盘语音

### 目标

让语音从“单次输入”升级为“成长复盘陪伴”。

### 功能范围

- 连续对话模式。
- 项目复盘语音流程。
- 学习复述语音流程。
- 周报语音访谈。
- 月报语音摘要。
- 语音中断和继续。
- 夜间静音。
- 敏感内容确认。

### 适用场景

- “陪我复盘这周学习。”
- “帮我整理项目卡点。”
- “我说一下今天状态，你帮我记。”
- “读一下这个月的成长总结。”

### 不做内容

- 不做完全免手动的常驻监听。
- 不做声音克隆。
- 不做复杂情绪声线。
- 不做自动医疗判断。

### 推荐方案

- STT：API 为主，可试验本地 STT。
- TTS：固定 API 声线为主。
- 本地部署：开始设计隐私模式。

### 原因

V2 语音应服务周报、月报和长期成长复盘。  
这时语音不只是输入方式，而是 Roxy 陪用户整理人生阶段的交互方式。

## 7.3 V3：本地隐私模式和高级语音成长助手

### 目标

提供更强隐私、更稳定的长期语音陪伴能力。

### 功能范围

- 本地 STT 可选。
- 本地 TTS 可选。
- API 和本地模式切换。
- 隐私模式。
- 离线基础提醒。
- 语音记录自动分类建议。
- 语音投喂知识摘要。
- 收入记录语音确认。
- 健康和心情记录隐私保护。

### 适用场景

- 用户希望私密记录心情。
- 用户希望本地记录收入。
- 用户希望离线进行学习复述。
- 用户希望 Roxy 在不联网时仍可提醒休息。

### 不做内容

- 不默认开启监听。
- 不未经确认保存敏感语音内容。
- 不提供医疗诊断。
- 不把语音情绪分析当作确定事实。

### 推荐方案

- STT：API 和本地双方案。
- TTS：API 高质量声线加本地基础声线。
- 本地部署：作为隐私优先用户的可选能力。

### 原因

V3 的用户已经积累了成长记录、记忆和项目资料。  
这时隐私和长期稳定性变得更重要，本地部署才有更明确价值。

## 8. 语音系统与成长目标的关系

语音系统必须优先服务五个方向：

### 8.1 学习

- 语音复述知识点。
- 口头记录学习时长。
- Roxy 语音提醒学习计划。
- 周报中总结学习状态。

### 8.2 健康

- 温和提醒休息、喝水、活动。
- 口头记录运动。
- 记录精力状态。
- 不做诊断。

### 8.3 项目

- 口述项目进展。
- 记录阻塞点。
- 梳理下一步行动。
- 语音复盘项目周进度。

### 8.4 赚钱

- 记录收入来源和金额。
- 记录兼职、项目变现、客户进展。
- 生成收入月度摘要。
- 敏感金额默认不公开播报。

### 8.5 长期成长

- 语音生成每日记录。
- 周报访谈。
- 月报朗读。
- 毕业阶段成长回顾。

## 9. 风险与边界

### 9.1 隐私风险

语音天然敏感。

规则：

- 不默认永久监听。
- 不自动保存敏感内容。
- STT 文本保存前让用户确认。
- 用户可以删除语音记录和转写文本。

### 9.2 打扰风险

语音回复可能打扰用户或周围人。

规则：

- 默认允许关闭自动播放。
- 夜间静音。
- 公共环境可切换文字模式。
- 收入和健康内容谨慎播报。

### 9.3 角色失真风险

声线不稳定会破坏 Roxy 的人格。

规则：

- 固定主声线。
- 不频繁切换音色。
- 不使用夸张情绪声线。

### 9.4 过度聊天风险

连续对话可能变成无目标闲聊。

规则：

- 连续对话优先绑定成长场景。
- 可选择模式：学习复盘、项目复盘、健康记录、收入记录、心情记录。
- Roxy 应帮助用户沉淀记录和下一步行动。

## 总结

RoxyPlan 的语音系统应围绕成长设计。

V1 先验证手动语音输入、固定声线和短语音回复。  
V2 扩展连续对话、周报月报和成长复盘。  
V3 增加本地隐私模式，让语音可以安全地承载健康、收入、心情和长期成长记录。

语音不是为了让 Roxy 更会聊天，而是为了让用户更容易记录、复盘、行动和成长。

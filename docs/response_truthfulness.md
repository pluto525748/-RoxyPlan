# V2.2 回复事实一致性

更新时间：2026-10-15

公开回复的事实优先级为：

1. 交互状态的确定性控制回复。
2. 真实 `ToolResult` 或批量结果摘要。
3. 查询结果格式化。
4. 可选模型润色。
5. `ActionClaimGuard` 最终校验。

只有匹配的写工具成功后，回复才能使用“已添加、已记录、已完成、已删除”等表述。成功的查询工具不能证明写操作成功；“没有记忆、没有计划、没有行动记录”等空数据声明也必须来自对应的成功查询结果。

最终守卫区分能力介绍、建议、完成断言与未来交易承诺。“我可以帮你记录”不等于已执行，也不能因为没有本轮工具而把正常能力介绍改成失败。正式保存声明（包括“我记住了”）必须有匹配的保存成功结果，计划或行动工具成功不能为记忆保存背书；没有结果时明确纠正，不伪造成功。

多句建议中的“已经按较高强度排出候选”“晚上不安排学习”与“没有加入计划”不能跨分句拼成一次已写入声明。计划变更断言在具体分句内判断动作、肯定／否定和完成语气；真正声称“我已经加入今天计划”的回复仍必须由写工具结果支持。

“你确认后我会保存／执行”只能描述当前真实合法的待确认操作。`VerifiedTurnContext.confirmation_pending` 提供有限脱敏事实，不能凭上一句助手文字创建交易；能力必须匹配，待确认仍不等于已完成。正常建议可以引导用户明确表达请求，但不能在没有 pending 时承诺短答会自动执行。

目标方向澄清（例如确认考试类型）与讲解中的操作概念不因分散出现“确认”和写动作而自动视作交易授权。普通聊天没有读取依据却声称“没有计划”等数据为空时，最小纠正该声明所在句，保留其余可独立成立的聊天；若整段仅该声明则仍使用确定性核验提示。真正的保存／完成／删除成功断言、跨域待确认、未核验空数据声明的保护继续生效，不原样放行无依据事实。否定与未来写动作跨句组合的其他既有误拦仍以当前状态为准，本批不宣称全部解决。

当前聊天轮没有执行工具，不得推翻上一轮真实成功操作。服务可以传递脱敏的最近核验事实，回复应分别说明本轮聊天、用户现实进展与程序记录；不根据当前对话编造旧工具结果。已完成项可诚实说明无需重复而不再写入，已删除／不可用项不能声称完成或改记行动。

基于已读取历史事实给计划建议时，“昨天你完成了某项”是以用户为主语的过去事实陈述，不因同一回复里出现“今日计划”就视作助手本轮写入；“我已更新／加入／完成计划”等助手或系统执行断言仍须有对应成功 `ToolResult`。误拦不能把已经生成的建议整段替换为泛化道歉。

空内容、`None`、超时或模型续写失败使用确定性降级文案。候选接受/忽略使用工具返回的真实候选 ID；部分成功逐项展示。内部 reasoning、异常堆栈、绝对路径和 Token 不进入 UI，诊断／异常输出不泄露私人正文。用户主动读取正式记忆仍遵守当前展示边界；敏感记忆宽泛展示改造暂缓，不在本文宣称已经完成。

批量回复逐项依据真实 ToolResult 聚合；没有基础润色文案时仍展示核验结果，不能让通用空回复降级覆盖实际成功／失败摘要。集合失效不隐瞒范围变化，失败只给确实适合原目标的可靠表达或入口。

配置 `deterministic_response_enabled=false` 只用于对照旧行为，不影响数据格式。

## 诊断

`interaction_diagnostics_enabled=true` 时，服务在内存保留有限轮次的结构化链路快照，并可显式导出 JSON。快照包含路由来源、特征类别、候选工具、解析状态、确认策略、工具结果、后置校验、Provider/模型和延迟；用户正文只保存长度与 SHA-256，不保存 API Key、推理文本、完整记忆或 Token。该开关默认关闭，也没有公开 Web 导出接口。

开关关闭时即使配置了诊断路径也不落盘；提前失败仍保留启用时应有的语义链字段。确认事实诊断仅保存脱敏能力和数量，不保存私人正文。临时诊断授权不等于永久修改正式设置。当前支持边界见 [capability_boundaries.md](capability_boundaries.md)，状态来源见 [interaction_state_machine.md](interaction_state_machine.md)，最新验证只在 [current_status.md](current_status.md) 维护。

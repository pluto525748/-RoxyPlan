# V1.8 业务对象解析

`BusinessResolver` 是不可信语义候选与真实本地工具之间的边界。它不负责生成聊天文案，也不直接读写 JSON。

## 输出状态

- `resolved`：工具与参数已经可以执行。
- `ambiguous`：存在多个合理对象，需要选择。
- `missing`：缺少标题、时长、正文或引用。
- `not_found`：没有真实对象匹配。
- `forbidden`：工具未注册、内容重复或违反业务约束。

## 领域规则

- 记忆：正式查询无需确认；候选审核校验真实候选 ID；归档、恢复和删除继续经过安全策略。
- 计划：检查必填字段、相似计划、当前日期、待完成状态和唯一目标；“刚才那个”优先读取当前 pending、成功工具返回的资源 ID、最近创建/更新对象和真实列表结果。
- 行动：明确记录可直接执行；普通进展陈述先询问；“记录这个”引用上一条用户陈述；当天重复内容不重复写入。

页面按钮也应构造受信候选后进入 Resolver 和 ToolExecutor，不应直接修改持久化文件。

计划写工具成功后还要重新读取真实数据，核对存在/删除、标题、时长、日期、时段和完成状态。后置条件不成立时返回 `postcondition_failed`，不更新最近对象引用，也不允许回复成功。

配置 `business_resolver_enabled=false` 仅用于兼容回滚。

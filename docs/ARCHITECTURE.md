# RoxyPlan Architecture

## 当前架构（V0.9）

RoxyPlan 当前是单机 Python / PySide6 原型，重点验证桌宠、聊天、状态动作、本地记忆、本地知识读取、成长闭环和本地模型交互。

当前没有独立后端服务，也没有数据库持久化。应用主要由 `frontend/pet_app.py` 启动，桌宠、聊天和设置仍在同一个桌面端进程中运行。

## 模块边界

- `frontend/`：桌宠窗口、聊天界面、气泡和动作控制
- `modules/`：模型调用、成长数据管理等可复用功能
- `data/`：本地提示语、人格数据、桌宠配置和知识库目录
- `assets/`：桌宠图片资源
- `docs/`：产品、架构和路线文档
- `tests/`：基础逻辑测试
- `backend/`：预留边界，当前未形成独立后端服务

## 当前数据流

1. 桌宠和聊天窗口由同一个 PySide6 应用启动。
2. 聊天窗口读取本地人格、长期记忆和 `data/knowledge/` 中的 `.txt` / `.md` 文件。
3. 普通消息构建 prompt 时加入人格、记忆和匹配到的本地知识片段。
4. 模型调用模块发送到已配置的兼容接口。
5. QThread / Worker 执行模型请求，主线程继续播放 thinking 动作。
6. `GrowthManager` 把计划、行动和复盘保存到被忽略的 `data/private/`。
7. 桌宠配置和提示语保持为独立 JSON 数据。

## 当前限制

- 聊天历史还没有数据库级持久化。
- 长期记忆仅支持昵称和用户显式保存的文本条目。
- 本地知识读取只做 `.txt` / `.md` 正文读取和关键词匹配。
- 知识回答没有独立引用 UI，也没有向量检索。
- 舞蹈动作已有播放框架和 8 帧透明 PNG 测试素材。
- 后端、语音、复杂文档解析、移动端和跨端同步仍是规划内容。

## 已实现与计划中

已实现：桌宠 UI、聊天、状态动作、设置面板、本地 JSON 数据、基础模型调用、私有记忆文件规范化、轻量知识读取、成长闭环和测试脚本。

计划中：独立后端服务、数据库聊天历史、完整文档解析、向量检索、语音、移动端和跨设备同步。

当前架构服务于原型验证，后续在需求稳定后再评估服务拆分和持久化方案。
